计算机系统概述

辨认概念的职责、条件与关系。案例和未注明原题的练习均为自编教学场景。

在平板上选好实验室和时段，点击“确认预约”。界面开始转圈；稍后出现成功提示。学生看到的是一次操作，计算机系统却完成了多处协作：平板接收触控，服务器检查时段并保存记录，通知回到平板，门禁以后再核对预约。先沿这个自编场景看清系统的边界，后面的硬件、软件和网络才有位置可放。

拉近一台机器，再拉远到整个服务

触控玻璃、处理器芯片、内存、闪存和网卡都有物理形态，属于硬件。预约程序、处理的数据和说明程序的相关文档属于软件。教程在概述中把一台计算机分解为硬件子系统和软件子系统。继续往下，硬件有 CPU、存储器、输入设备和输出设备；CPU 承担运算与控制等功能。软件则按支撑作用分为系统软件与应用软件：操作系统管理资源，编译工具支持程序开发，预约应用实现检查时段等业务规则。

这些框表示“由什么组成”。把平板、交换机和服务器放回校园，观察问题变成“机器之间怎样交换数据”。网络提供连接环境，交换机自身仍有芯片、存储和控制软件。因此硬件、软件和网络可以同时出现在一个服务描述中；它们切分的尺度需要说清。

“存储器包括主存与外存”是教材图 2-1 的概述视角。换到 I/O 观察轴，磁盘也是由控制器和接口管理的外设。两个描述可以同时成立。CPU 读取主存中的指令或数据，与操作系统从磁盘文件装入数据，有不同机制；后文再把它们展开。

同一批部件，在运行中承担不同动作

平板的触控部件把动作变为输入，CPU 执行界面程序，显示部件呈现等待状态。请求经过网络抵达服务器，服务器上的预约应用检查时段，借助系统软件管理的运行与存储资源保存结果。随后返回的信息让平板显示成功。这里的先后取决于消息和业务条件；硬件组成图的上下位置并不表示执行次序。

系统软件与应用软件也有依赖关系。预约程序可以借操作系统的接口读写文件、使用网络，让资源管理集中在系统软件中。编译工具参与生成程序的开发过程，不必在每次点击预约时重新运行。浏览器、数据库等具体软件还可按职责进一步描述，2.3 将讨论这些层次。本节先抓住支撑与业务目标这条线。

同一设备可以有几种同时成立的描述

机房服务器能运行预约服务，也能换成文件服务；门禁控制器嵌在门禁设备中，主要完成凭证判断和驱动开门。教程图 2-2 给出通用计算机与嵌入式计算机的一种常见分类，再分别列个人计算机、网络服务器、超级计算机，以及通信、家电、可穿戴、医疗、交通、国防、金融等嵌入式用途。这是按主体功能粗分的示意，教材同时提醒技术融合会带来交叉。

电话手表同时具有可穿戴设备和移动通信终端特征；通信平板可以从个人计算机与通信终端的角度描述。这里是同一粗分类中功能融合带来的交叉。后面的用途、集成与部件，则是不同观察轴。平板、电话手表或智能手机具有多种功能。题目若明确教材分类或“以应用为中心、资源可裁剪”的嵌入式特征，就按其口径判断；工程讨论若关心应用扩展能力，还可以另外描述它具备哪些通用能力。先确定问题和范围，避免仅凭“可以装应用”排除所有嵌入式特征。

教材还列出结构、性能、规模、软件构成和特征、用途及服务对象等分类维度。结构看怎样组织部件，性能看处理表现，规模看资源与系统大小；软件构成和特征看软件怎样组织或工作；用途和服务对象看为谁完成什么任务。一个“大规模、高性能、采用多核结构、运行多种应用”的服务器，几种描述可以同时成立。具体指标怎样比较留到 2.9。

再看同一个门禁控制器。“嵌入式”描述它在较大设备中的用途定位；“采用 SoC”描述多种系统功能集成到芯片的形态；“含 CPU 或专用处理单元”描述内部部件。把 SoC、GPU、嵌入式系统排在同一层当互斥类别，比较对象就发生了变化。GPU 和 DSP 的计算特点留到 2.2，实时性与安全后果留到 2.4，它们也需要各自的判断条件。

功能如何实现，目标是否达成

门禁中的校验或图像处理，可以由 CPU 执行软件完成，也可以采用专用逻辑加速。FPGA 在设计时由描述和配置确定逻辑，运行时仍以物理电路工作。选择实现方式，要同时考虑处理需求、升级灵活性、数据搬运、成本和功耗。硬件加速改变局部的执行方式，是否改善整个服务要测量；2.9 会说明整体性能的时间基准。

回到开头：平板出现成功提示，门禁却查不到预约。仅有显示输出，无法证明服务器已保存、门禁拿到了相应数据。先核对成功提示代表哪个动作，再沿请求、保存和查询的证据检查边界。这一步只定位需要验证的环节，不预先断言某个组件故障。组成视角帮助找到对象，运行视角帮助找先后，用途视角帮助理解设备为何如此设计；同一个系统可以由这几种图共同解释。

01 / 自编 · 观察尺度

把交换机放大查看，可见芯片、存储与控制程序。怎样描述它与网络的关系最准确？

B 同时说明单机组成与跨机尺度。A 混合切分维度；C 忽略控制软件；D 把连接错当时间，连接本身不表示先后，须有明确的顺序语义才能解释为过程。

02 / 自编 · 运行与开发

预约应用由编译工具生成，运行时借操作系统接口使用网络。由此能推出什么？

C 区分支撑出现的阶段。A 只有特定动态编译等实现条件下才可能发生，题干未给；B 混淆开发工具与业务；D 把执行依赖当物理包含。

03 / 改编 · 相邻 SoC 误解

某门禁控制器面向特定用途，使用含 CPU 与专用单元的 SoC。哪组标签可以同时成立？

A 的三个标签回答三个问题。B 强迫不同轴互斥；C 用部件推出系统用途；D 忽略软件仍控制或配置系统。该题借相邻记录的混轴考法重新写成完整场景，未声称原题。

04 / 改编 · 多功能设备边界

教程称某些多功能设备可归入不同父分类。遇到电话手表的归属题，首先应核对什么？

D 保留教材粗分类与交叉条件。A 是输入输出形态；B 是应用扩展特征，不能单独排除嵌入式；C 是来源维度，均不能独立决定主体用途。

05 / 自编 · 改变观察轴

概述图把磁盘归外存，I/O 图又把磁盘作为外设。如何判断？

B 允许同一对象有不同职责描述。A 未核观察轴就判冲突；C、D 忽略主存地址访问与外设控制/装入的机制区别。容量不决定访问路径。

06 / 自编 · 实现条件迁移

把校验算法从 CPU 软件改成 FPGA 配置逻辑后，哪项判断仍成立？

C 区分配置描述与物理实现。A 混淆开发形式与运行实体；B 忽略未改环节和开销，只有其它环节与搬运成本可忽略等条件才可能近似同比例改善；D 无依据删除系统组成。

07 / 自编 · 过程推演

平板显示预约成功，服务器查询不到记录。当前证据能支持的第一步是什么？

A 按证据定位。B、C 都把一种可能原因当已确认事实；D 将本地输出扩大为全局目标。若服务端已给可核持久化成功凭证，证据会更强，但此题没有给出。

08 / 自编 · 图的逻辑

在组成图中，应用程序指向操作系统的箭头标为“依赖服务”。它表达什么？

D 尊重箭头标签。A 把软件依赖变成物理包含；B 把依赖变成先后；C 增加未给数量约束。改变箭头含义须同步改变图例。
