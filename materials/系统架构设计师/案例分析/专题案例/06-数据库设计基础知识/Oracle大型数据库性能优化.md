# Oracle 大型数据库性能优化：索引选择、聚簇与 SQL 调优（试题四，25 分）

## 题干（原题抄写）

> 试题四（25分）。某大中型企业使用 Oracle 建立经济信息统计大型数据库应用系统。虽然硬件和网络环境较好，系统实施后整体性能仍较差；随着业务量和信息量增长，数据库存取速度变慢、存储效率下降。专家建议从以下方面优化：① 调整服务器硬件、操作系统和 DBMS 配置，尤其改进磁盘 I/O；② 优化索引的建立和使用；③ 对逻辑上经常需要连接且较稳定的基本表使用聚簇（Cluster），使其物理邻近存放以减少搜索时间；④ 调优 SQL，并针对每条 SQL 都建立相应索引。
>
> **问题一（13分）**：针对每条 SQL 语句都建立索引的建议是否合适？简要说明理由。
>
> **问题二（12分）**：结合经验列举 4 条 SQL 语句优化的基本策略。
>
> （原文一处将 Cluster 拼作 “Culster”；随题参考答案对问题二又注明“列举其中 5 个小点即可”，与题干“4条”不一致——来源矛盾原样保留。）

## 考场答案与采分要点

**问题一：不合适。**
1. 索引会占用额外存储；插入、更新、删除需要维护相关索引项，增加写入开销。
2. 优化器按表大小、统计信息、选择率和成本选择索引访问或全表扫描。低选择率、小表或统计信息失准时，索引可能不被采用。
3. 索引类型应匹配查询：B 树适合范围与有序访问；哈希类结构在 DBMS 支持且查询为等值匹配时可考虑。
4. 聚簇适合稳定、频繁的连接或范围访问；若数据频繁更新或访问关系不稳定，维护成本可能抵消收益。
5. 应结合执行计划、统计信息和真实负载测试索引效果，不能保证“每条 SQL 有索引”就会使用索引或提高整体性能。

**问题二：SQL 优化策略（题干要求 4 条，随题参考答案又称 5 个小点即可；从以下策略中选出至少题干要求的数量）**：
1. 只检索必要的列和行，避免无用数据传输与处理。
2. 减少不必要的多表查询；重复执行的复杂汇总可评估物化视图，并考虑其刷新与数据时效成本。
3. 在语义等价且执行计划有利时，以非相关子查询替换相关子查询；OR 改写为 IN 也需验证语义和计划。
4. 使用集合化或批量处理，避免嵌套游标和多重循环。
5. 事务完成后及时 COMMIT，缩短锁的持有时间；不能每条语句都机械提交，以免破坏事务原子性。

## 解析与易错点

- 索引、聚簇和 SQL 改写都需与实际访问模式匹配。通过执行计划、统计信息和 I/O 负载定位问题，再用代表性数据验证改动；不能把索引数最多当作性能目标。
- 不能认为 OR→IN 改写总会更快。
