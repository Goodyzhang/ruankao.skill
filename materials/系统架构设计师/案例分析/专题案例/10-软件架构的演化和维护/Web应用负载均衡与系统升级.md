# Web 应用负载均衡与系统升级（题库第六节题目 23，9+8+8＝25 分）

## 题干（原题抄写）

> 阅读以下关于 Web 应用系统负载均衡的问题，回答问题 1 至问题 3。某电子商务公司的主要业务是书籍、服装、家电和日用品的在线销售。随着业务和用户规模扩大，现有网上交易系统无法正常处理不断增长的请求流量。公司讨论两种升级方案：采用高性能主机系统，或采用负载均衡集群，最终采纳集群方案。
>
> **问题 1（9 分）**：从系统可用性、可伸缩性和应用特点三个方面说明为何没有采用高性能主机系统。
>
> **问题 2（8 分）**：按传输层负载均衡和应用层负载均衡分类，说明 DNS 负载均衡和 HTTP 重定向服务器分别属于哪类，并简述实现方式（200 字以内）。
>
> **问题 3（8 分）**：LVS 集群需支持购物车，并保证 VIP 用户的服务质量。分别说明这两种需求带来的负载均衡问题及改进方案（200 字以内）。

## 考场答案与采分要点

**问题 1（不选高性能主机）**：单机难做冗余，故障可能使全站不可用；纵向扩容成本高、可伸缩性较差；Web 请求通常是大量简单任务并发处理，而高性能主机更擅长复杂单任务或有限并发。集群可通过多节点冗余与横向扩展提升可用性和处理能力。

**问题 2（按本题库参考答案）**：DNS 负载均衡归为**传输层类**：同一主机名配置多个地址，DNS 轮流返回不同节点地址，引导不同客户端访问不同节点。HTTP 重定向归为**应用层类**：重定向服务器返回新 URL，客户端再向目标节点发起请求。

**问题 3**：
- **购物车会话**：购物车属于应用会话数据。可将会话状态放在具备容错能力的共享会话服务器／存储中；也可配合会话黏滞，但需考虑节点故障时状态丢失。
- **VIP 服务质量**：使用应用层负载均衡的客户端亲和性（sticky session），把同一用户的请求持续路由到同一应用实例，减少会话／缓存数据在节点间迁移。

## 解析与易错点

- 高性能主机是纵向扩容，成本与能力提升不成比例且单点风险高。
- DNS 分流发生在域名解析时，受 DNS 缓存与 TTL 影响，不是逐个 HTTP 请求精确调度；HTTP 重定向会增加一次客户端往返。
- 客户端亲和性可减少状态迁移，但不能替代会话状态的容错存储。
