# Java企业级应用-三层框架与轻量级框架选型案例


## 原题（网站题号 4～6 合并：试题五，25分）

**试题五（25分）**　阅读以下关于Java企业级应用系统开发架构的叙述，根据要求回答问题。

【说明】某软件公司承担了某中小型企业应用软件开发任务，进度要求紧迫。项目组方案论证中，刘工建议采用J2EE 5.0和EJB 3.0开发（J2EE定义了标准的应用开发体系结构和部署环境，EJB是J2EE的基础和核心；EJB 3.0相比EJB 2.1有很多改进）；杜工建议采用Struts、Spring和Hibernate轻量级开源框架结合的方式（基于POJOs的开源框架被广泛引入Java企业应用开发，与重量级EJB框架相比有很多优点）。项目组认为两种建议都合理，结合当前项目实际，最终采用杜工的建议。

## 来源答案与解析（网站原文）

- 题4：表现层（对应View）、业务逻辑组件层（对应Controller）、持久层（对应Model）及各自功能。
- 题5：三框架特点（Struts粒度粗开销、Spring依赖注入+AOP无分布式、Hibernate反射透明映射灵活限制对象模型），网站注明“以上意思对即可给分”；详细解析补充iBATIS对比。
- 题6：轻量级侧重减小开发复杂度、处理能力减弱（事务弱、无分布式），适合中小型应用；EJB强调高可伸缩性、容器承担基础结构服务，适合大型应用；解析补充二者互补与EJB轻量化趋势。

## 核验答案（考场作答）

### 【问题1】（6分）

**考场答案**（150字内）：（1）表现层（对应View）：建立应用界面，展现数据，负责组件显示粒度、页面跳转与事件触发，服务客户端请求；（2）业务逻辑组件层（对应Controller）：支持由表现层发起的业务数据逻辑处理，隐藏业务对象复杂性；（3）持久层（对应Model）：实现持久化存储，与数据库等外部资源交互。

**采分要点**：三层各2分（推定）：层名＋对应MVC角色＋功能各占其半。

**详细解析**：这是Java企业应用经典的层次式架构（表现层→业务逻辑组件层→持久层），与MVC的View/Controller/Model对应。判别线索：题干问“划分为3个层次”，教材口径固定为这三层——不要答成“表示层/业务层/数据层”之外的J2EE四层容器模型（客户端层/Web层/业务层/EIS层），那是J2EE体系结构口径，两种口径不能混。

**常见失分表达**：把持久层写成“数据库层”；漏掉括号里的MVC对应关系（阅卷按对应关系给分）；超150字。

### 【问题2】（12分）

**考场答案**（200字内）：Struts是表现层框架，标签库与样例丰富、使用广泛，但组件粒度粗、框架类限制死板，带来额外代码开销；Spring是业务层轻量级框架，基于IoC与AOP，依赖注入装配Bean并实现事务管理，模块可分离配置，但不具备分布式能力；Hibernate是持久层O/R Mapping框架，轻量封装JDBC，反射机制实现透明性，映射灵活支持1:1至m:n，但限制对象模型。结合方式：Struts负责Web表现与调度，Spring以IoC容器组装组件并管理事务，Hibernate负责持久化，以Spring为纽带集成为SSH架构。

**采分要点**：三框架特点各4分（推定），其中“结合方式”合入Spring点或单独给分：三框架职责+Spring整合关系。

**详细解析**：特点题按“层定位→机制→优点→缺点”四步答。机制关键词：Struts→MVC/Front Controller+标签库；Spring→IoC容器+AOP声明式事务+POJO；Hibernate→O/R Mapping+反射透明性+HQL。结合方式的答题骨架是“谁负责哪一层、谁粘合谁”：Struts收发请求，Action交由Spring托管，业务对象由Spring注入，数据访问委托Hibernate的SessionFactory/模板。网站解析还给出iBATIS对比（自动SQL vs 手写SQL），可作为扩展素材，不进采分点。

**常见失分表达**：只写优点不写缺点（每框架都要求优缺点）；把Spring写成“MVC框架”；漏“结合方式”整段。

**知识点链接**：[ORM、Hibernate 与 CMP2.0 设计思想](https://github.com/Goodyzhang/ruankao.skill/blob/main/materials/%E7%B3%BB%E7%BB%9F%E6%9E%B6%E6%9E%84%E8%AE%BE%E8%AE%A1%E5%B8%88/%E7%AC%94%E8%AE%B0/%E7%9F%A5%E8%AF%86%E7%82%B9/13-%E5%B1%82%E6%AC%A1%E5%BC%8F%E6%9E%B6%E6%9E%84%E8%AE%BE%E8%AE%A1%E7%90%86%E8%AE%BA%E4%B8%8E%E5%AE%9E%E8%B7%B5.md)、[ORM 与持久层技术框架](https://github.com/Goodyzhang/ruankao.skill/blob/main/materials/%E7%B3%BB%E7%BB%9F%E6%9E%B6%E6%9E%84%E8%AE%BE%E8%AE%A1%E5%B8%88/%E7%AC%94%E8%AE%B0/%E7%9F%A5%E8%AF%86%E7%82%B9/06-%E6%95%B0%E6%8D%AE%E5%BA%93%E8%AE%BE%E8%AE%A1%E5%9F%BA%E7%A1%80%E7%9F%A5%E8%AF%86.md)

### 【问题3】（7分）

**考场答案**（200字内）：轻量级框架侧重减小开发复杂度：基于POJO、不依赖容器，开发调试效率高，开源社区提供大量现成组件；代价是事务功能弱、不具备分布式处理能力，适用于中小型企业应用。EJB重量级框架强调高可伸缩性：与基础结构服务相关的问题和底层分配都由容器/服务器处理，容器通过减少数据库访问次数及分布式处理提供系统性能方案，适用于大型企业应用。二者互补而非替代，EJB 3.0也在轻量化。

**采分要点**：轻量级4分（侧重点+弱项+适用规模）、重量级3分（侧重点+容器机制+适用规模）（推定）。

**详细解析**：对比题的答题骨架是“同维度对仗”：开发复杂度↔基础服务托管、事务/分布式能力弱↔容器提供性能与分布式、中小型↔大型。选型回到题干情境：本项目“进度要求紧迫+中小型”，正对应轻量级的优势面，这也是杜工方案被采纳的论证逻辑。

**常见失分表达**：只答“轻量级好/重量级差”没有维度化对比；漏“适用规模”这半句（阅卷常设此点）。

**知识点链接**：[SSH 轻量级 J2EE 分层映射](https://github.com/Goodyzhang/ruankao.skill/blob/main/materials/%E7%B3%BB%E7%BB%9F%E6%9E%B6%E6%9E%84%E8%AE%BE%E8%AE%A1%E5%B8%88/%E7%AC%94%E8%AE%B0/%E7%9F%A5%E8%AF%86%E7%82%B9/13-%E5%B1%82%E6%AC%A1%E5%BC%8F%E6%9E%B6%E6%9E%84%E8%AE%BE%E8%AE%A1%E7%90%86%E8%AE%BA%E4%B8%8E%E5%AE%9E%E8%B7%B5.md)
