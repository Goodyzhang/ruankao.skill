## 二、课程明确表达的得分逻辑

### 1. 以三个子题完成情况为主线

课程明确：低分最常见的三类问题，是项目背景没有完成、子题二没有按题回答、正文实践偏题或空洞。背景需写清项目时间、功能、作用、技术与本人职责。技术名和功能名需要解释用途，不能整段罗列。

课程短证据：

- “大的方向的得分点就在于这三个子题。”
- “技术是用来去实现论题的。”
- “他该回应的，他全部都写了。”

方法提炼：先把题目的对象、动词、数量和约束拆成可核对条目。每条都找证据，不能只看总篇幅、语感、词汇量。子题二若要求“特点、适用场景”，只写定义仍不完整；问“分析、设计、开发全流程”，只写某阶段也不完整。

### 2. 论题统领技术；改稿修因果，不靠重复关键词

高并发题可使用微服务、缓存、异步、弹性伸缩。问题在于把整篇的解释对象改成“微服务架构优缺点与适用性”，或只展示服务拆分如何方便开发。该题需要解释并发压力如何形成瓶颈、措施如何改变瓶颈。

课程完整改稿保留银行投研篇的数据接入、因子挖掘、策略开发、回测和安全服务，主要增加了业务压力、对应题面方法及解决效果的连接。HPA 段也保留原有阈值、服务与调度方案，增加选举投票秒级突增的业务特征和“水平扩容”的定位。

技术复核：点题应该是有效因果链，不能仅在每句前加“高并发”。服务拆分不自动降低延迟；如果共享数据库仍是瓶颈，扩容业务实例可能增加后端压力。

### 3. 子题二全面回应，主体择重点深入

高并发题明确要求六个方面：缓存设计、异步处理、限流降级、数据库优化、服务拆分、水平扩容。课程建议单独一段各用一句说明，再选三至四方面结合业务展开。47 分篇六项均有提及，但部分解释很弱；48 分篇真正解释了含义与用途，教师认为更值得借鉴。

方法提炼：分别记录“已提及”和“按题完成”。出现六个名词只能算提及；解释了对象、手段和作用才算理论回应。独立回应段是常规训练安排；若题目要求已在主体清晰完整完成，不因缺固定段位判未答。

### 4. 业务细节是主要论据，技术细节继续加分

课程要求写“在该项目中怎样做”。LLM 41 分篇说 Copilot 生成桩与驱动、JaCoCo 统计覆盖率、Jenkins 跑回归，但没有交代哪段业务规则、哪个接口、哪组输入、预期结果及判定方法。技术名很多，项目证据仍少。

课程短证据：

- “智能识别了什么代码，生成了多少测试用例？”
- “写了什么功能的测试桩和驱动？”
- “具体需求，然后转成测试用例……输入参数等详细的。”

方法提炼：至少给一个能复述的闭环：业务事件/输入→作者判断与约束→处理过程→输出/异常→验证。用例生成题尤其要交代输入需求、生成对象、用例字段、覆盖目标、人工校验或自动断言及失败修订。

### 5. 摘要第二段概括论题及主体，背景解释项目

车辆动力学 39 分篇在摘要后半反复写团队负责模型建立、接口定义、流水线落地，未概括 LLM 如何用于测试。项目背景又展开团队工作清单，时间、交付、困难、方案的顺序混乱。课程将其视为摘要和背景职责错位。

方法提炼：摘要后半用主体同序概括方法及作用；不要用团队履职清单占满摘要。背景应让人理解项目做什么及为何需要本题方法；本人岗位职责用紧凑语句表达，实施细节进入主体。

### 6. 提交稿用连续文章，训练结构留在辅助层

课程反复强调不把“项目背景”“正文”“结尾”“回应子题二约 300 字”等教学标签直接写进考场文章。不把一级二级标题当成段落内容，不以问题一/问题二的案例答题列表代替论文。

边界：训练文档可以保留段次、写作映射、评分表、批注和段名；“可抄写稿”正文隐藏这些辅助标签。摘要框与正文框按照实际考试界面填写，勿误删界面字段。课程也说正文一二三编号“倒无所谓”，因此“有编号直接不及格”不是其完整主张。

### 7. 不比较无关方案；结尾可按字数调整

课程建议未要求比较时少写“选 A 还是 B”的长比较，直接进入业务措施。47/48 范文仍有比较句，教师认为可删冗余，而非导致全部不合格。

课程说明背景约 500 字，结尾不属于单独三个子题；时间或字数紧张时可压成一段约 200 字。前面不足则多写，前面够了则缩短。

方法提炼：权衡确实解释关键决策时可以保留一两句；比较不是每段必填。结尾压缩前先确保题面要求的效果、问题及解决办法已有落点，不能将题面明确要求的内容一起删掉。

## 三、不能机械固化为 Skill 的口述

| 课程表达/现象 | 必须保留的正确内核 | 发布技能应如何表述 |
| --- | --- | --- |
| 子题二不回应就不合格，编错也比不写好 | 漏掉核心要求是严重风险；冷门题也要尝试解释 | 无正式评分细则，不宣称官方一票否决；模拟练笔应核对机制、补足合理解释，不能奖励技术错误 |
| 每段第一句要点题；48 分例子后两段未重复点题仍认可通过 | 总体论述对象清楚；段内说明措施如何服务论题 | 先检查全篇摘要、理论、实践的关系；句首未重复题名不是单独扣分理由，不能靠词频判题意 |
| 39 分 LLM 可能误判，无摘要可能未还原 | 材料完整性影响结论 | 分开记录课件标分、老师推测、当前可见材料；不能把未展示当未作答，不能确认误判 |
| 正文不能直接抛 AI 使用后的问题 | 要先交代 AI 承担什么业务任务，再说问题 | 原题子题三明确问问题、局限及措施，可以问题驱动；允许“应用背景→出现问题→原因→措施→验证”的自然叙述 |
| 六边形类似六个接口，又说明六是虚数 | 内外分离、以端口和适配器适应外部变化 | 不是固定六接口，不从几何边数推导端口数；重点写依赖向内、业务核心不依赖具体外设 |
| 六边形是层次式发展、DDD 落地框架之一 | 可以结合 DDD 识别业务边界 | 六边形与 DDD 可以组合，不建立必须先层次式、必须 DDD 的谱系；限界上下文不等于端口 |
| LLM 子题二问生成方式，口述又建议去写缺陷归类等 | 要展示 LLM 的具体用法，避免测试阶段科普 | 原题范围优先。子题二只回答用例生成实现路径；缺陷分析等放在确实要求的部分，不替换“用例生成” |
| 看 47 分通过推论当年没有卡论文 | 完整扣题有价值 | 一篇样本不能推出考试整体通过率或评卷政策；不写入 Skill |
| 有状态服务“不适合短生命周期容器” | 状态、长连接与缩容要特别处理 | 容器可运行有状态负载；写持久化、会话粘性、分片归属、优雅退出、重分配等实际条件 |
| 反规范化、MQ、K8s 一起“实现扩容” | 同一摘要应逐项绑定技术作用 | K8s+伸缩策略负责副本调度，MQ 缓冲解耦，反规范化减少连接；不能混成一种机制 |

转写中“万人模板”“子题骂”“red is”“corporal/coppers”“LM”“HAP”等需据课件和上下文规范为万能模板、子题二、Redis、Kubernetes、LLM、HPA；不把音译当术语。课程结尾提到的考试日期、时间距离不能作为当前考试安排。

优先替换段示例（保留本来的教师发布业务）：

> 教师集中发布作业时，批改请求与发布请求争用计算资源。我将发布确认和后台批改分离：发布服务先持久化作业与批改任务，返回受理状态，再通过消息队列通知批改工作节点。批改容量不足时保留排队状态，暂停低优先级画像刷新，已接收的作业不会因降级丢失。消费者按作业编号和版本去重，失败任务限次重试后交人工处理。我在同一批发布请求下分别核对发布延迟、积压任务量和最终完成数，确认降级后核心发布仍可用，恢复后积压能够消化。

规则校验：完整扣题使它具有通过基础；技术丰富度较低不是唯一问题。该篇可作为“保证完整”的正例，不能作为“一致性机制已经充分”的正例。

## 六、LLM 41 分例子的具体改法

原写法的弱点是“使用插件→自动生成→覆盖率提升→接流水线”的流水账。可将可见的配置变更业务改为以下原理清楚、可检验的练笔段：

> 在配置变更回归中，我让 LLM 以接口规约、变更事件格式和现有单元测试作为输入，生成覆盖“审批通过但基线未更新”的异常用例。具体需求规定：配置版本变为 v2 后，基线服务必须在限定时间内收到事件并更新对应基线；超时则进入补偿流程。模型生成正常投递、重复投递、延迟投递和消息丢失四类场景，为消息客户端生成可控制返回值的桩，并把基线版本与补偿状态写入断言。测试人员逐条核对断言与需求的一致性，修正模型把“发送成功”等同“消费完成”的错误预期。执行时，延迟与丢失场景稳定复现了原有遗漏，研发补上补偿后重跑相同用例，确认版本更新与补偿状态都符合要求。

这段没有用“生成测试”四字代替过程：输入是什么、模型生成什么、场景如何区分、测试人员核对什么、缺陷怎样复现和验证，都有明确落点。它没有把业务修复全部归功于模型，作者、LLM、执行器和研发的职责可分辨。

## 七、建议交给 Skill 的增量规则

1. 输入先记录题面与材料完整性。原题、三个子题、附加约束、局部/全文、还原/原稿均需分清。
2. 要求覆盖图增加“题目对象”和“动作”，检查相邻知识替题、阶段介绍替实现路径、名词罗列替解释。
3. 摘要第二段和实践段以论题为中心，增加“现有内容如何服务本题”的桥梁；不得按关键词频次判断偏题。
4. 批改优先次序：漏题/答错对象→技术机制→业务证据与本人行动→结果一致性→结构表达。技术丰富不抵消题面缺失，扣题清楚也不豁免技术错误。
5. 写范文时完成题面全部方面，主实践可组合为三段。十段式保留训练映射与隐藏注释；可抄写稿不显示背景、正文、结尾等教学标签。
6. 少写工具清单与无关选型比较；保留能解释关键决策的一两句权衡，主要篇幅给业务过程。
7. 不将模型能力、平台能力和人工工作混写；写清输入、输出、约束、验证、失败处理。生成内容必须有可判断的正确性依据。
8. 结果指标必须有对象与条件；目标值、观察值、验收值分开。课程范文中的“保证一致”“线性扩展”“有状态不适合容器”照样复核。
9. 评分固定训练量表，课件分数/老师自估/本轮估分分别记录；局部材料只评可见部分，未知不当遗漏，不声称官方扣分阈值。
10. 对每个批改问题给原句短证据、题意落点、影响、替换句/段；改后再检查全篇摘要—理论—实践—结尾一致性。
11. 核心学习规则与应试成文分层保存：学习笔记可给页码证据，正式练笔稿不加出处、防御说明和内部代号；公开发布只保留泛化方法与自拟例子。
