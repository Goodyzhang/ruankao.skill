# 论文批改：相关性、证据与训练估分

用于评分、诊断失分及校准评阅。先读 [paper-review.md](paper-review.md) 的共用方法；范文生成见 [paper-writing.md](paper-writing.md)。

## 1. 十二条审查规则

| 规则 | 实质判断 | 不足时怎样修 |
| --- | --- | --- |
| P01 审题对象与动作 | 保留论题、前言和小问的对象、动词与范围，不能用更熟悉的相邻主题替代 | 将本题要求写为待证明主张，重新选择材料 |
| P02 论证链相关性 | 全篇主题、小问回应、段落主张、业务实例及结果相互支持 | 保留可用技术，重写业务瓶颈、作用机制和验证；只加题目关键词不算修复 |
| P03 全面回应与重点展开 | 题干列出的方面全部有实质落点，深入实例再按题意选择或组合 | 补齐缺项或理清组合映射；已在主体完整回应时不强制另加概述段 |
| P04 业务实例与本人行动 | 业务角色、对象、规则或状态、交互及本人决策可辨认 | 把对象清单展开为一个具体过程，说明为什么这样处理 |
| P05 效果与因果 | 效果测量了该措施要改变的对象，比较条件明确 | 改用直接指标，说明验证条件；开发效率不能独自证明并发优化 |
| P06 技术机制 | 原理、边界、执行主体和异常处理成立 | 修正具体机制，不能因例文得分高就照收技术错误 |
| P07 项目背景 | 说明建设原因、功能作用、相关技术与职责，规模相称 | 将产品和功能罗列改为“做什么、怎样做、服务谁” |
| P08 摘要与主体 | 摘要点题并概括正文主张，论点顺序和结果一致 | 从完成的主体回填，删去未展开的新论点 |
| P09 结尾闭合 | 成效回扣主题，不足具体并接对应处理或改进 | 区分已解决与待改进，消除核心功能尚失效却称成功的矛盾 |
| P10 材料完整性 | 区分原稿缺失、截图未展示、未还原与作者明确未写 | 缺失可判断失分；未展示记待核，不按零分推断 |
| P11 写作口径 | 沿用已授权的真实或模拟口径，检查可行性与内部一致性 | 模拟稿直接修补设计与结果；真实性说明留元数据 |
| P12 可追溯评阅 | 每个判定有题目要求、原文位置和具体证据，给分与扣分不重复 | 提供可用替换稿，改后回填覆盖表；不附加无依据惩罚 |

## 2. 相关性要阅读全文判断

检查顺序：题目要求作者证明什么；作者实际主张什么；例子展示了什么；结果验证了什么。四者存在断点就定位断点。

- 高并发题详细介绍独立部署、团队并行开发与技术异构，仍可能漏掉并发瓶颈和优化过程。技术丰富不能补回未回答的小问。
- 同一题中，服务拆分若解释了计算隔离、热点伸缩、争用控制并提供验证，就可以成为有效论点。
- 六边形架构中的 DDD 可以帮助识别核心；还需说明端口、适配器和依赖关系。不能把“用了 DDD”直接判为错，也不能把完整 DDD 段自动算成六边形实践。
- 宽泛的架构风格题允许分层、消息通信、仓库等组合。评价每种风格在何处、如何协作、例子是否成立；不自行增加“只能选一种”的要求。
- 摘要、全面回应段与相邻段已建立明确对应时，某一段没有重复题目关键词，不构成单独失分。段首点题是改善可读性的建议，不能变成关键词门槛。
- “运用了正确术语”只证明提及；“有业务名词”只证明关联。主张与实例间仍需机制或规则支撑。

## 3. 训练评分表

优先使用实际取得的本题评分依据。没有逐点权重、用户希望模拟评分时，可在读稿评分前冻结以下 **75 分训练表**，标记 `inferred-training`。若题目结构特殊，先按原题调整并记录理由，不能看完分数再倒推权重。

| 维度 | 满分 | 判断对象 |
| --- | ---: | --- |
| A 题意与要求覆盖 | 20 | 主题与任务对象是否一致；小问、限定范围及要求方面的实质覆盖 |
| B 理论及机制正确 | 20 | 定义、分类、职责、关键交互、适用条件和异常路径是否成立 |
| C 业务实践与本人决策 | 20 | 实例颗粒、决策理由、实施过程、问题定位和处理是否足以支撑主张 |
| D 结果验证与前后一致 | 10 | 效果、基线、条件、因果；项目设定及摘要正文结尾的一致性 |
| E 结构与表达 | 5 | 内容职责、衔接、篇幅与可读性；标签和重复是否影响表达 |
| 合计 | 75 | 每维给短证据、实得分及未给分理由 |

高分表示证据充分且机制成立；中段表示部分完成或论证不足；低段表示对应内容大部缺失、偏离或关键机制错误。维度分需要解释，不按词频、段数或产品数量计算。

这是内容质量的训练估分。不要把课堂所示成绩当作本轮目标分，不能为了复现 37、48 或 52 分而调整评价。课程标分、教师自估与本轮训练分分列；存在差异时解释材料范围或判断差异。

### 材料不全怎样给分

只对能独立判断的要求或维度评分；部分维度再拆单元时先给定该单元分母，保持总分预算不变。输出“已见部分得分 / 可评满分”，未知项列出待核。确需全篇区间时：下界为已确认得分，上界为已确认得分加未评满分；区间内不判确定及格与否。

截图标注“子题二未还原”不能改成“原稿没有子题二”。全文完整且确认漏答时才按覆盖缺口评价。只见一段的问题诊断可以很确定，但不能由此虚构全文分数。

### 不能重复惩罚

每个问题记录一个原因，例如“六边形题被 DDD 过程替代”。覆盖评价说明漏了哪些任务，实践评价依据实际展示的论证深度；不再加“偏题扣分”“关键词不足扣分”等额外惩罚。不同维度确实存在独立缺口可分别解释，同一个缺口不能换名重复扣。

结构、标题、段数只按实际影响评价，不覆盖技术和实践维度的已得分。不因八段、混合架构、少产品名或授权模拟无真实仓库证据，设置及格封顶。

## 4. 评阅输出顺序

1. **总体判断和优先问题**：先说回答了什么、最影响得分的断点是什么；已完成内容保留。
2. **逐项覆盖表**：原题要求、位置和短证据、完整/部分/缺失/未展示、修改落点。
3. **训练评分**：有评分请求再给；列适用依据、各维实得及理由，材料不完整则保留未知。
4. **可执行修改**：每项给优先级、原句与位置、对应任务、影响、可复制替换稿。改例子时修正机制与验证，不只在句首补关键词。
5. **改后复核**：按请求交付替换段或全文；同步摘要、背景、实践、结尾中的论点、名称和数字，分别统计摘要和正文字数。

学习笔记、辅助映射表、评分解释与考场正文分开。正文保持匿名、完整和自然表达，不能将评阅过程标签或真实性辩解写进范文。

## 5. 用示例检查评阅是否跑偏

修改本方法后，可用 [paper-calibration.md](paper-calibration.md) 的合成样例做独立试评。评价能否定位真正断点、保留正确内容、处理未知项并给出有效修改；字面复述规则或分数靠近例文成绩，都不能证明批改质量。
