# 论文范文：从审题到完整考场稿

撰写、扩写或重写范文时读取。共用边界、十段预算与交付复核仍见 [paper-review.md](paper-review.md)；本文解决怎样选材料、展开论证和形成自然正文。

## 1. 先确定这道题要证明什么

下笔前形成一张小表，保留原题动词：

| 项目 | 要写清的内容 |
| --- | --- |
| 论题对象 | 本题究竟考高并发、六边形架构、需求分析，还是某项技术在特定环节的应用 |
| 子题要求 | 逐条拆出介绍、解释、比较、分析、设计、实施、问题、效果等动作及限定范围 |
| 项目矛盾 | 一个能解释本题必要性的业务触发，例如集中会商读压与长时模型计算争抢连接 |
| 实践主张 | 每段准备证明什么，用哪个业务对象、流程和验证结果支撑 |

高并发题可以使用微服务，主张应落到并发瓶颈、隔离、吞吐和响应；六边形架构可以结合 DDD，必须继续说明业务核心、端口、适配器、依赖方向及替换验证。不能仅替换题目名称，沿用另一篇的全部论证。

前言和子题明确限定“测试用例生成”时，围绕需求解析、生成、预期结果、校验与应用展开。其他 AI 测试能力只在服务该论述时简述，不能凭更宽的论文标题替换小问。

## 2. 复用项目的业务实质

- 沿用当前已确认的项目名称、职责、规模、时间和材料用途，不固定任何行业或金额。
- 背景先解释旧流程为何影响业务，再选择与本题有关的功能和技术。功能要交代谁使用、处理什么、产生什么作用；技术说明用在何处、解决什么问题。
- 通用背景保留稳定项目身份，按本题调整挑战与过渡。省略无助于当前论证的产品清单、版本号和并列模块名。
- 换行业或换项目时重新组织业务关系和句式，不只替换专有名词、金额或“三大模块”的数量。
- 课程关于项目级别、近年完成、团队周期与金额相称的建议可作素材选择参考；不能把建议升级为所有题目的硬性采分条件。

## 3. 给每个实践段准备可展开的实例

先用一句话写段落主张，再检查实例能否证明它。优先沿同一业务链串起三段，以便共享对象、输入与状态。

| 论点 | 实例至少应展开到的颗粒 |
| --- | --- |
| 用例模型 | 一名参与者的目标、前置条件、主要交互、成功结果和一个替代流程；不能只列参与者与用例名 |
| 静态分析模型 | 业务概念、关系及多重性、关键属性与职责；接口类、工具类清单不能代替领域分析 |
| 动态分析模型 | 某个实体的当前状态、触发事件、条件、状态迁移与后续动作 |
| 高并发优化 | 峰值请求如何形成瓶颈、措施作用于何处、处理与资源分配怎样改变、同条件如何验证 |
| 六边形架构 | 外部请求经哪个适配器调用哪个输入端口，业务核心通过哪个输出端口访问外部能力；替换外部实现如何验证核心不受影响 |
| ABSD | 按题要求交代六项活动；将需求到架构、构件分配、文档、复审和演化落到项目决策与制品，可将相关活动组合成三个实践段 |

每段采用“业务问题—原理与选择—本人措施—运行过程—问题处理或验证”组织。原理一两句即可，主要篇幅留给具体业务。出现问题时解释定位依据和措施怎样起作用；不要求每段另造一次故障。

技术细节服务于主张。若段落主张是“通过用例分析澄清审批规则”，后半段应展示规则冲突与用例细化，单独增加 Redis 和集群信息不能补足分析过程。

## 4. 形成自然且可检查的全文

默认按两段摘要、两段背景、一个全面回应段、三个实践段、两段结尾组织；题意优先。辅助映射表和段号注释可保留在学习稿外围，考场正文连续成文。

- 使用“我据此……”“在……流程中……”衔接，不将“项目背景”“回应子题目二”“正文实践”“结尾”写成正文里的解释标签。
- 清除每一两句就出现的“状态识别：”“事件与转换：”式微型提纲，直接叙述对象、事件和行为。必要的技术小标题可按题意保留，不以存在标题推断不合格或 AI 生成。
- 先写主体，再回填摘要第二段。摘要的论题、三个主张、顺序与效果均能回指正文，不能只概括用了什么架构。
- 摘要第一段压缩项目和职责，不展开所有模块。背景第二段再介绍相关功能、技术和规模，避免与摘要重复占用实践篇幅。
- 结尾先写完成状态与对应效果，再写一至两个具体不足和改进。已解决问题与尚待改进分清，不能一边称验收成功，一边留下未处理的核心业务失效。
- 不用“未产生任何影响”“所有问题彻底解决”掩盖因果缺口；按用户已确定的真实经历或模拟口径写完整结果。

## 5. 与 AI 协作的三个可复用请求

**构造项目背景**：给出当前固定项目设定、真实或模拟口径、目标论题、两段各自职责及字数预算；要求先交代业务矛盾，再解释相关功能与技术，避免套用示例句式。输出后核对匿名名称、角色、日期与规模。

**扩写主体**：提供完整题目、项目背景和三段论点；要求每段选一个业务实例，写清输入、规则或状态、本人决策、过程与验证，按题面覆盖全部方面。不要只说“加入项目实际”。

**整篇复核**：要求逐条定位小问证据，检查“主张—实例—结果”的因果关系，区分缺失与未展示，给替换段并同步摘要、正文、结尾。评估和评分按 [paper-scoring.md](paper-scoring.md)，不能让模板相似度代替内容判断。

## 6. 交付

用户要求完整范文时，交付完整摘要与正文；框架、得分点表和背诵抓手可作辅助，不能代替文章。统计摘要与正文各自字数，按当次题卷或练笔预算核对。最终复读时重点检查题意、技术机制、实例证明力、项目与指标一致性。
