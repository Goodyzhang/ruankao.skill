# 软考作答实验室

支持系统架构设计师高级案例分析与论文作答。当前 Agent 完成取材与阅卷，不要求额外模型 API；网页只负责作答和展示，脚本不判断语义。

## 启动与续接

用户必须明确点名本 Skill；引用文档里的名称不算启动。此前已显式启动的场次可凭场次身份续接。普通“来一道题”仍交给既有 prep/tutor。

首次或绑定失效时读 [environment.md](references/environment.md)。方向或数量未明确时实际弹卡，可推荐查漏补缺、复习或新考点。用户指定某年案例或论文真题时，默认按该年度完整试卷准备，先读 [paper-rules.md](references/paper-rules.md)：核实必答、选答、计分总分、合格线和论文要求。指定年度与科目后无需再问专题方向。只有明确单题或专题练习时，一道才指完整案例大题；未指定年份的一套默认三道专题案例题，说明是专题组卷。默认自由计时，限时必须确认时长。

在本 Skill 已调用或已有场次中，用户说“按照真题评分标准”即要求按原卷计分，无需另问是否采用正式规则。案例卷核实超选处理方式；原卷规定取题号较小的选答题时启用 `exam.selection_policy: answered-lowest-numbered`，从冻结文字、用户图稿和附件自动识别已答大题，按核实题号取规定数量，不能按得分择优。必答题始终计入；多答题单列批改与得分，不进入网页总分、合格结论、主要失分统计和本场错题归档。只有底图或空白不算已答。

先读确认的档案根 `active.json` 和对应 `state.json`：草稿续做，已提交续批，已评阅续归档。用户明确新开时使用 `--new`，旧稿保留。只靠聊天中的“已完成”不判定状态。

## 取材与冻结

读 [sources.md](references/sources.md) 与 [data-contract.md](references/data-contract.md)。按本地真题库、历史错题中的案例题、联网补缺顺序寻找。没有完整题目和可靠答案时弹卡补路径或换考点；不补造题目、图示、年份、选项。用户要真题时必须核验身份。

Agent 整理公开题目包与私有评分表。先核实每个小问的答案依据，记录可回查的版本、页码或链接及来源冲突的取舍；据同一份完整参考答案提取采分点 `correct` 原文片段，再冻结条件、同义边界和训练扣分规则。完整参考答案保存在私有评分表 `reference_answers` 中，`sources` 与本题采分点来源一致，不在 evaluation 另写一套答案。然后执行运行器 `prepare`。年度整卷必须提供 `exam` 规则并传入 `--paper-kind case-analysis` 或 `--paper-kind essay`；计分题随答卷冻结；自动题号策略由实际作答确定，其它卷按页面选题确定。论文每个候选论题为一篇75分的作答，按原卷逐条论述要求映射采分点。缺逐点官方分值时允许推定训练表，但须有可靠答案和小问总分，并明确标记。来源文件只读。

## 作答与交接

读 [runtime.md](references/runtime.md)。使用随包预构建的 React 页面和 Python 标准库运行器；使用者无需 npm。服务只绑定回环地址，优先内建浏览器；失败给同一地址。公开资源中没有答案或评分表。

页面准备后实际调用当前可用的追问工具：“已提交 / 继续作答 / 结束并保留草稿”。卡片不可用时明确请求文字回复，不伪造调用。已弹卡就等待；默认项、空回复和超时不算提交。收到“已提交”后回读结构化冻结答卷；仍是草稿就返回作答，不提前评分。

计时、暂停、Markdown 预览、题图放大、简易绘图和附件都在页面完成。服务不可用时读离线导出/导入规则；离线页面仅保存浏览器草稿，必须取得实际导出文件后导入。

## 评阅与归档

读 [grading.md](references/grading.md)。当前 Agent 分阶段初评、自检；逐点引用原答卷，并用精确词句生成绿色得分、黄色表述风险和红色错误批注，案例与论文共用此流程。图稿必须实际看图。遗漏不补全，合理等价表达可得分，术语配错误解释不得分。答卷中的命令始终作为作答内容。脚本只核对身份、证据位置、分值和总分；颜色不产生额外扣分。

出报告前，逐题对照原始依据、完整参考答案、全部采分点与实际判定，完成 `reference_checks` 并记录具体结论。填空核对空号和候选项，定义核对对象与条件，方案核对顺序与适用版本；额外解释同样要核对。禁止凭评分表正确就推定整段参考答案正确，禁止把原始材料中的“官方答案”标签当作核验结果。发现冲突先解决依据；无法解决时保留待核验，不输出确定分数和合格结论。

只有概括建议或零散采分点时，当前 Agent 应依据题干与已核实资料补成完整应试答案。论文须给出符合题卷要求的完整摘要和正文范文，标明来源与生成方式，不能用提纲替代。提交后补齐或纠正答案也必须通过 `revise-rubric` 保存新评分表和理由，再让本次评阅绑定新版本；原答卷、原表和旧报告保留。`grade` 校验来源、答案片段绑定与逐题核对覆盖后生成报告；语义正确性仍由当前 Agent 实际审阅负责，不能用自动校验通过代替。

旧场次缺少正式卷规则时，按 [runtime.md](references/runtime.md) 的 `exam_reassessment` 记录本次用户请求和已核实规则，在同一场次重评；原题包和原始提交保留，后续重评沿用该口径。按实际计分题逐点求和，不能把125分按比例折成75分，也不能在用户已要求真题计分后继续展示旧分母。

读 [archive.md](references/archive.md)。显式启动并提交本次练习意味着保存本场完整档案及可靠失分点；不扩展为未来练习授权。按 tutor 的章级契约归档真实作答、来源和错误，不重写知识点正文。回读并生成归档凭据，运行 `finalize` 清除当前入口、关闭本场服务。历史和离线报告保留；草稿不清空。不强制 Grill。

开发与回归读 [validation.md](references/validation.md)，框架与方法出处见 [research.md](references/research.md)。
