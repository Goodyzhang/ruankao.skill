# 运行与交接

从当前完整 Skill 定位脚本，不硬编码用户名。以下占位参数由 Agent 用当前路径替换并正确引用；公开安装包会携带 dist，使用者不运行 npm。

```sh
python3 scripts/lab.py prepare --root '<已确认档案根>' --pack '<题包JSON>' --rubric '<私有评分表JSON>' --source-root '<原图目录>' --count 1 --true-question
python3 scripts/lab.py serve --session '<prepare返回场次>'
python3 scripts/lab.py status --session '<场次>'
python3 scripts/lab.py wait --session '<场次>' --timeout 25
python3 scripts/lab.py grade --session '<场次>' --file '<Agent评阅JSON>'
python3 scripts/lab.py finalize --session '<场次>' --file '<回读归档凭据JSON>'
```

`prepare` 默认复用 active；显式新开才 `--new`。专题组卷 `--count 3`。指定年度整卷时，`--count` 是原卷候选大题数量，另传 `--paper-kind case-analysis` 或 `--paper-kind essay`；必须已有核实的 `exam` 规则。已有场次的题包身份与正式卷不一致时，保留旧场次，先说明如何续接或另开，不能默默沿用错误分母。限时添加 `--mode timed --minutes 已确认数值`，自由计时默认。第一次点“开始作答”开始计时；自由模式可暂停；限时后台到点冻结最近成功落盘的答案，前端同步尝试保存最新输入。断网/未落盘的输入只能在客户端恢复，不承诺后台读到它们。

`serve` 打印实际随机端口与场次身份，并默认请求系统浏览器打开 `http://127.0.0.1:端口`。若当前有可用内建浏览器，使用 `serve --no-open`，先发正文链接，再用浏览器工具打开，避免重复弹窗；无桌面也可用 `--no-open` 并明确手动打开。`browser_open_requested` 只说明发起了打开请求，不能据此声称页面已显示；`browser_open_failed` 时保留同一正文链接。

Agent 保存实际进程会话标识，在可持续运行的终端/进程工具中启动服务，不把前台进程超时退出当作后台就绪。用 `status` 核验 `url` 非空：它探测本场 `/api/health` 的身份，只返回真实可达的回环地址；过期 `service.json` 或别的场次端口不会成为入口。不得猜固定端口、把路径当 URL、用 `localhost` 或 `0.0.0.0` 替换入口。不要绑定公网、用未知服务PID结束别人的服务，或把题库作为静态根目录。服务公开白名单 index/offline/report/static/figures，不公开私有 JSON。POST 校验本场凭据、Origin、Host、身份、revision，避免旧页面串答。请求超限或磁盘失败只显示失败，保留输入。

页面顶部显示原卷要求、满分和单科合格线；必答题固定计入；手动选题模式通过下拉框选齐后开始，自动题号模式可直接开始并作答全部候选题，交卷按内容确定计分范围。右侧作答区上方再次显示当前小问描述；论文提供独立摘要和正文输入框。页面提供全小问导航，正文纯文本输入及本地 Markdown/KaTeX 预览。作答区常驻正文撤销按钮，每个小问最多记录20次编辑；暂停或没有记录时禁用，刷新后从新的编辑开始记录。浏览器未保存稿只在打开页面时读取为恢复候选，正常输入不重复显示恢复提示。Excalidraw 提供基本图形、箭头、文字、分组、撤销、缩放；题图可设底图，PNG/JPEG/WebP 可上传或粘贴。自动保存、手动保存与交卷串行。交卷确认提示空白，但允许提交。图稿与同一份导出 PNG 一并冻结；保存失败不冻结。

## 正文入口与交卷监听

准备完成后，必须先发普通正文（可用即时正文/进度消息，但不能只有思考、工具结果或卡片），再打开内建页面并等待。正文包含：试卷名称、当前作答状态、实际可点击的 127 链接、交卷后的动作。例如用实际值填好后发送：

> 2021 年论文试卷已就绪，当前为草稿。[打开作答页](http://127.0.0.1:实际端口)。请在页面完成作答并交卷；我接着检查交卷状态，收到冻结答卷后开始评阅。

此例的年份和端口都是占位，不能原样发给用户。默认自动打开系统浏览器的场景，服务可能先打开窗口；正文仍必须在任何等待或卡片之前发出。用户说“给我 URL”“我要 127 开头的地址”时，立即检查 `status`，在正文给链接；失效则重启同一场次并给新链接，不再次弹状态卡。

默认调用 `wait --session ... --timeout 25`。它只读文件，每秒检查一次，最长允许 60 秒，并返回紧凑结果：

- `submitted`：已有本场 `submission.json` 且身份与哈希通过；回读冻结答卷后进入评阅，不另问“是否提交”。
- `timeout`：仍为草稿；继续有时限地等待，不评分、不弹卡、不因一次超时结束监听，也不逐次刷状态消息。
- `service_unavailable`：草稿服务不可达；检查自己启动的进程，恢复同一场次服务、重发入口后继续。不能只显示“正在监听”。
- `graded` / `archived`：按实际状态续归档或结束，停止本次等待。

使用当前 Harness 实际提供的后台命令与等待工具维持会话内监听；不可用时改为一次卡片/文字交接并明确监听已暂停。用户消息优先于等待：要链接就给链接，要继续就续等，要停止就保留草稿并关闭自己的服务；新请求按其范围处理。会话结束后，只有已建立的真实调度才支持自动续接；否则明确让用户回到当前聊天发送“已提交”以恢复检查，不承诺永久后台阅卷。停止练习或归档后不留下轮询，也不擅自创建系统定时任务。

卡片只用于缺必要信息、用户主动选择或无法继续监听时的交接。**任何卡片前，同一响应都必须先有非空正文**；已有页面时正文包含核验链接和当前状态。卡片标题中的 URL 不代替正文。已弹卡就等待，不重复弹卡。若卡片返回的是“显示 URL”等自由文本，按请求给正文链接，不能按默认选项处理。卡片不可用则用文字说明实际限制。用户自报“已提交”仍先 `status` 并回读 `submission.json`；草稿不能批。

停止练习保留草稿，关闭自己启动的服务；下次用相同场次重启，不换身份。

## 离线兜底

无可用Python时，Agent依照数据契约手工准备本场private题包/评分表、初始state及public目录；复制预构建dist为static，生成与脚本html相同的JSON嵌入页面并设置offline:true。不把答案嵌进去。可由另一可用本地环境先 prepare 再拷贝完整公开目录。file:打开 offline.html 不依赖 fetch；草稿仅localStorage。题图设底图若file:禁止读取时使用上传相同原图，不谎称直接读盘。

交卷会导出提交JSON，用户将导出的实际文件路径提供给Agent；若Python恢复可用执行 `import-answer --session ... --file ...`，没有Python时按同样身份/版本/小问集合/附件/提交状态核验并原子保存，交接记录明确未经运行器验证。离线答卷计时不冒充服务端计时。没有拿到实际文件，仍停在交接。

提交后 page 只读。服务重启会从文件恢复，无需旧进程；不绕过浏览器访问审批。评分后同服务可看 /report.html，离线 public/report.html 持续可读。finalize 成功会清除 active，并由服务监测到 archived 后关闭。

## 修改评分表

事实错误经核验后：`revise-rubric --session ... --file ... --reason ...`。保存旧表和理由；原答卷不动，新评阅绑定新hash，旧HTML/JSON保留。不要向用户暗中修改标准。

新报告只读取当前冻结评分表中的完整参考答案。旧场次的答案若在 evaluation 中，先按原始依据核实并移入新评分表：填写 sources，从正文提取 correct，执行 revise-rubric；随后更新 evaluation.rubric_hash，移除 evaluation.reference_answers，逐题完成 reference_checks，再调用 grade。禁止直接复制旧错误正文或只改版本值跳过核对。原报告在 reviews 中保留，submission.json 不动。

## 按真题规则自动计分

用户在已调用 Lab 后说明“按照真题评分标准”，按原卷配置案例 `exam.selection_policy: answered-lowest-numbered`（须核实原卷确有此超选规则）。页面无需勾选即可开始，全部候选题均可作答；交卷和离线导入由运行器依据实际答案、附件和用户图稿自动确定计分题。必答题加题号最小的规定数量已答选答题计入总分，多答题仍需完整评阅和参考答案，单列展示且不进入总分及失分排行。

旧场次没有 exam 时，在本次 evaluation 加入 `exam_reassessment: {title, exam, request, reason}`，记录用户原话、已核实规则与修正原因，然后调用原有 grade。已归档场次也可这样重评；原始题包与提交保持不变，新的范围保存在 state 中并供后续重评沿用。只筛除未答且不计分的候选题判定，不把多答题混入总分；不可按125分比例折算。完成归档回读后照常 finalize，保证 report/index/offline 都显示同一正式结果。

评阅页默认展示三色批注的 Markdown 原答卷，原始文本可展开，参考答案位于下方。右侧引文突出实际得分或错误片段，点击后滚动到对应批注；案例与论文使用同一套逻辑。已有报告更新静态资源后可按原证据着色，精确词句和黄色风险提示需要 Agent 在新的评阅版本中补充 focus 与 warnings，原答卷和旧报告保留。
