# 软考单题讲解、诊断与归档

本 Skill 只处理一道当前题目：输入完整性、分级、讲解、可选 Grill 与确认后归档。中级学习计划交给 `soft-exam-prep`，高级计划、案例与论文交给 `soft-exam-architect-prep`；完整历史对话导入分别交给 `soft-exam-organizer` 或 `soft-exam-architect-organizer`。

首次需要本地资料、归档位置未绑定或原路径失效时，读取 [first-use.md](references/first-use.md)。先讲题，真正归档前再完成位置引导；已有有效绑定直接复用，路径选择不代替本题归档授权。

已学章节或指定专题的复习册制作、续写和局部修订交给 `soft-exam-review-book`；旧错题作为制作素材时不启动当前单题或历史导入流程。

## 执行与续接契约

本节统一交互时序；[运行时契约](references/runtime-interaction.md) 规定实际工具适配。先完整读取本文件，首次需要交互时再读运行时契约；普通讲题不提前加载 Grill 或知识库写入规则。

> **门控要求**：已选择卡片模式且当前工具可用时，先给可见讲解或反馈，再在本轮结束前实际调用相应提问工具。不能只发文字预告后结束，也不能让用户只看到卡片而没有本题讲解。工具适配、已显示卡片和中断补发按下文及运行时契约处理。

在会话中按题保留状态，不为状态记录写入知识库：

```text
question_id: 当前题的来源消息及题号；批量题用稳定题号，不因排序改号
attempt_state: unknown / not_attempted / correct / wrong
explanation_sent: 是否已输出本题讲解
phase: explain / grill_gate / grill / archive_gate / write / done / blocked
interaction_mode: card（默认）/ text（用户明确选择）；保留选择的真实事件
round: 有实际作答的练习轮数（0–3）
last_question: 最近交互的用途、内容、选项映射及关联 question_id
last_result: 真实工具返回或文本答复；未回答则 pending
archive_scope: 本题的授权来源、目标和允许操作；未授权则为空
batch_scope: 明确授权的题号集合、来源消息、目标和操作；没有则为空
per_question: 每题的上述状态、写入位置及实际回读结果
```

| 当前状态或用户结果 | 下一步 |
|---|---|
| 完整题目，尚未讲解 | 先输出第 2 节讲题正文，再决定下一步；需要门控卡时按下文在本轮结束前实际调用 |
| 用户明确只讲解、结束或换题 | 完成请求后结束本题，不追加练习或归档确认 |
| 已讲解，用户明确要求本题或列明批次归档，未要求先 Grill | 核对目标后直接写入并回读；不增加 Grill 门控 |
| 已讲解，已作答，未要求直接归档，未表达 Grill 偏好 | 本轮讲解后实际调用 Grill 门控卡；已有可见讲解不重复全文 |
| 用户明确开始 Grill，已有可靠答案与作答上下文 | 沿用已完成的本题讲解，简短说明本轮练习目标，再实际调用第 1 道练习卡 |
| 未作答、作答未知、快速讲或跳过 Grill | 已授权且可归档则写入；否则可归档题在讲解后同轮实际调用归档确认卡，其它题结束 |
| 练习收到实际答案 | 本轮先给对应判别词和错因的反馈，再实际调用下一题卡或归档确认卡；最多 3 轮 |
| 归档已授权或确认返回同意 | 在已确认目标内写入并回读；不重复索取同一授权 |
| 用户拒绝归档 | 结束本题 |
| 工具缺失、报错或中断恢复 | 核对最近成功步骤和用户选择，从未完成动作续接；先核对是否已有真实卡片，按运行时契约补齐缺失动作 |

### 同轮讲解与实际调用

适用条件：`interaction_mode=card`，且已确认当前会话有适合本次问题的提问工具。“同轮”指同一次助手处理过程，在结束回复或等待用户前完成讲解与真实调用；可以由可见正文消息和工具事件依次组成，不要求特定 API 的单条消息同时含 `content`、`tool_calls` 字段。

- 写讲解或反馈前，先按状态表和用户最新指令决定本轮是否需要门控。需要时，按“可见正文 → 实际提问工具调用”完成，不以“稍后发卡”“要不要 Grill？请回复”等文字代替调用。
- 本题尚未讲解时，先按第 2 节讲清题目；已收到练习答案时，先反馈再出下一题。已有讲解后用户选择开始 Grill，沿用该讲解，不为发第 1 道练习重讲全文。
- 题干、选项和调用参数放在真实工具调用中，不在正文伪写卡片。工具名称与字段以当前会话为准；Antigravity 通常为 `ask_question`，其它客户端使用其实际暴露且适用的提问工具。
- 调用后已有真实选择就继续相应步骤，不要求用户另发“继续”；卡片已显示但未答时等待，不重复发送，也不把默认项或空返回当成答案。
- 漏卡、裸卡片、工具失败和中断的恢复统一读取 [运行时契约](references/runtime-interaction.md)。补发前先核对实际事件和最新指令；已经显示的卡片不能因为缺正文而再发一次。

结束前按条件判断：用户明确只讲解、结束、换题或拒绝归档时按其选择收尾；只说“不 Grill”仅跳过练习，是否归档仍按已有授权或确认流程处理。仍需门控、工具可用且尚未调用时，必须先完成调用；已发卡待答时等待；工具不可用时说明具体限制并保留未完成状态。未作答不进入 Grill，也不妨碍正常结束或归档确认。

### 新题边界与悬挂保护

新题重新建立作答、练习和交互状态。授权只从仍有效且明确包含本题的 `batch_scope` 派生；范围之外的新题不继承旧授权。一次“归档”不自动覆盖其它题。批量题逐题推进，受阻题记录原因，其它已授权且材料完整的题可继续。中断后从实际未完成题恢复，先回读疑似已写入的条目；已完成内容不重复写。

**悬挂判定**：上一题仍有已说明但未完成的讲解、练习或归档步骤，且用户未明确结束、换题、拒绝归档或放弃该题时，保留为悬挂题。仅发送新题不自动视为放弃旧题；新题独立建立状态并正常讲解，在正文第一行简短提醒一次：

```text
⚠️ 上一题 [题目标识] 仍待 [实际未完成步骤]，已保留进度。
```

- 提醒使用真实状态：可能是讲解未完成、练习待答、归档待确认或已授权写入尚未完成；已经取得授权时不能写成“尚未确认归档”。明确只讲解且已讲完的题目不构成待归档义务。
- 题号、年份未知时使用来源消息标识，不猜测。新题输入不完整时也可附提醒，但不为补旧题阻塞新题的输入 Gate。
- 同一次换题只提醒一次，不另发旧题卡片，不自动续做或归档旧题，不把旧卡片的答复算入新题。
- 悬挂状态保留在 `per_question` 中；用户回到旧题时核对该题已有授权、真实答复和实际写入，从未完成步骤继续。明确放弃或处理完成后关闭该悬挂项。

## 工作流

### 0. 输入 Gate

1. 获取完整题干、全部选项或子问题、图表、公式、单位、限定词和题源标记；多张图按题目顺序合并。
2. 图片无法读取时，使用会话中的 OCR 文本、可访问附件或当前可用视觉/OCR 能力；仍不能可靠取得内容时，请用户补充清晰截图或文本。
3. 裁切、遮挡、模糊或关键字符不确定时标为 `[不清晰]`。只要会改变答案，就停止并请求补充；不得猜题、补选项或根据答案反推题干。
4. 同一材料含多道独立题时先编号。用户已指定题号或批次范围时按范围逐题处理；否则询问本轮先处理哪题，按实际工具容量分页。每题独立维护作答、练习、授权和写入记录，不合并成一道练习或一条错题。

材料完整后直接继续，不为形式确认而中断。

### 1. 题源与分级

按“明确考试来源 → 题型结构 → 考查角度与深度 → 单个关键词”判断，简要说明：

```text
题目归属：软考明确 / 软考知识域相关但题源未确认 / 非软考或证据不足
级别：软件设计师-中级 / 系统架构设计师-高级 / 两者共有（归档前待确认）
依据：截图来源标记、题型、考查深度或知识域；置信度：高 / 中 / 低
```

- 题目主题相近不等于软考真题；没有可靠来源时如实标为“软考知识域相关但题源未确认”。
- 共有主题证据不足时保留“两者共有”，先讲通用原理；需要辨析考查角度时再读 [question-classification.md](references/question-classification.md)。
- 用户要求章节定位或需要归档时，再读 [chapter-routing.md](references/chapter-routing.md) 对应级别的映射。普通讲题不因出现设计模式、算法或公式就自动加载 Grill。
- 非软考题仍可讲解，但不归档到软考知识库。

### 2. 讲题

默认按以下骨架输出。用户要求简答时可以压缩，但答案必须有最短充分理由。

```markdown
## 题目复原

## 考点与判别词

## 解题链

## 答案与选项分析

## 迁移提示
```

- 说明决定答案的题干词、边界条件或计算结果。
- 选择题逐项说明；计算题定位概念、公式或计算错误发生的位置。
- 标题、表格、列表和代码块之间保留合理空行；标题层级不跳级。
- `quick` 场景可以给出变式答案；标准讲解和 Grill 场景的变式题先等用户作答。用户明确要求先练习时，先可靠解题，练习答案留到其作答后揭示。
- **收尾即调用**：本轮需要门控且工具可用时，讲解完成后直接调用已确认适用的提问工具，再按实际结果继续或等待；不以文字预告代替调用。用户只讲解、直接归档、结束或工具不可用时按对应分支处理。

### 3. 决定是否进入 Grill

输入阶段先记录 `attempt_input`：`unknown`（未说明）、`not_attempted`（明确未作答）或 `attempted`（给出了答案或过程）。完成可靠解题后，才把 `attempted` 解析为 `correct` 或 `wrong`。

| 最终状态 | 讲解后的动作 |
|---|---|
| `unknown` / `not_attempted` | 不主动 Grill；已有授权则归档，否则可归档题询问确认，其它题结束 |
| `correct` / `wrong` | 未要求直接归档时，按已确认交互模式询问是否 Grill |

- 用户明确要求本题或列明批次归档且未要求先练习时，直接进入写入，不额外询问 Grill；明确要求先 Grill 再归档时，保留授权，完成练习后写入。
- 用户明确要求 Grill 或深度追问，且已有题目、作答上下文和可靠答案时，可直接进入 Grill。
- 用户明确说“不 Grill”或“快速讲”时跳过 Grill。
- 卡片工具、调用时序和恢复统一遵循前面的“执行与续接契约”。已作答（`correct` / `wrong`）且未要求直接归档、不 Grill 或结束时，在讲解后同轮实际调用 Grill 门控卡，不把发卡留给用户再次催促。
- Grill 门控卡只用于选择“开始 Grill / 只看解析 / 结束”，不要求填写理由，也不提前显示正确答案或把用户说明文字拼进问题。进入 Grill 后按诊断契约提供内容选项，卡片点选或已确认文字模式答复均不要求填写理由。

### 4. Grill：按诊断状态追问

确定进入 Grill 后读取 [grill-diagnostic-contract.md](references/grill-diagnostic-contract.md)；组织题目和干扰项时再读 [grill-question-design.md](references/grill-question-design.md)，已在上下文的内容复用。诊断、选项映射、反馈和收尾以诊断契约为准。

答错时验证候选错因，答对时检验关键条件迁移；不能仅凭一次误选认定用户的内在理由。检索已知可访问的同考点真题以校准考法；缺资料时说明实际缺口，继续可靠且明确标注的变式，不把未检索写成“未找到”。最多 3 个有实际作答的回合，原理辨析与关键条件迁移都正确才说明本轮已验证；到上限仍未通过时如实记录。

### 5. 归档

仅“软考明确”或“软考知识域相关但题源未确认”的题目可归档。普通讲题后仍可询问归档；用户明确只讲解、不归档、结束或换题时按其选择收尾。已有明确授权则直接使用，不为本题或已授权批次重复确认。

写入前读取 [knowledge-base-contract.md](references/knowledge-base-contract.md)。确认本题在授权范围内，沿用已明确的考试级别与目标；位置未知时按首次使用指引补齐绑定，路径卡不扩大授权。只更新本题必要段落，回读题干、选项、答案、原作答、Wiki-link 和标题。

明确的批量授权，例如“把第 1–3 题归档到这个已确认目录”，覆盖列明的题目和目标；每题仍分别保存状态与写入结果。范围不清、目标不明或覆盖冲突时只澄清受影响部分；单题授权不能扩成整批，新增题也不自动加入原批次。历史对话导入仍交 organizer。

## 边界

- 归档授权只覆盖用户明确指定的题目、目标与操作；未经明确同意不得创建或修改知识库文件。
- 没有可靠答案依据时说明证据不足并停止归档。
- 可使用 toolkit 初始化的知识资料与真题转录；题目或答案未经核验时保留不确定性，图示缺失时先补齐。
