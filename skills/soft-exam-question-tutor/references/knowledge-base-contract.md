## 根目录与目标

公开 Skill 不预设可写知识库根目录。首次归档时，优先使用用户或工作区指令明确给出的 Vault 相对根目录；若未给出且无法从现有 Vault 结构唯一识别，先让用户确认根目录和目标文件，确认前不得创建目录或写入文件。下文用 `<软考根目录>` 代表已确认的 Vault 相对根目录；不得写入设备绝对路径。

| 级别 | 知识点目标 | 错题目标 |
|---|---|---|
| 软件设计师-中级 | `<软考根目录>/软件设计师-中级/NN_知识域.md` | `<软考根目录>/软件设计师-中级/软考-软设-错题本.md` 的对应章节 |
| 系统架构设计师-高级 | `<软考根目录>/系统架构设计师-高级/知识点/NN-章名.md` | `<软考根目录>/系统架构设计师-高级/错题本/NN-章名-错题.md` |

优先沿用当前 Vault 的章级笔记、命名和汇总错题本。旧笔记或模板只用于查重与格式参考，不迁移、不删除、不双写。仅在用户确认归档且目标文件不存在时创建必要目录和文件，不批量预建空文件。

## 写入前检查

1. 核对本题属于用户已授权的题目、目标与操作范围；明确的批量授权对范围内各题有效，不重复索取相同确认。范围不清或操作超出授权时，只澄清受影响部分。
2. 确认 `<软考根目录>` 与目标文件。未配置且无法唯一识别时，询问用户；确认前不创建目录或文件。
3. 确定归档级别；“两者共有”沿用用户已指定的目标级别，未指定时才询问。归档目录选择不改变题源判定。
4. 按文件规模读取：小文件可全文读取；较大的汇总笔记先检查 frontmatter、相关标题、目标章节及相邻边界，仅在无法确定插入位置或需要全局结构时扩大读取。目标不存在时先查看同级目录的命名与格式。
5. 用规范化后的题干关键句和选项检索目标错题库，包括本批次已写入内容；查重不能只覆盖当前读到的段落。同题已有时报告命中位置，不重复插入；若已明确授权更新，按范围补充，否则保留既有条目。需要未授权的覆盖或出现内容冲突时再询问。
6. 搜索已有知识点标题；存在时复用最精确标题，不另造同义标题。
7. 确认正确答案有可靠依据；证据不足时停止归档。

仅修改必要段落，保留未涉及的人工内容、章节顺序与复习状态；不要用局部读取到的内容重建整个文件。批量任务中有单题受阻时，说明原因并继续其它已授权且材料充分的题。

## 知识点写法

### 软件设计师-中级

按 [chapter-routing.md](chapter-routing.md) 选择 D01—D12 知识域。已有小节时在对应位置补充；没有时创建新的 `##` 小节。需要更细粒度锚点时使用 `###`。

新文件只在对应章级文件确实不存在时创建，默认命名为 `NN_名称.md`：

```markdown
---
tags:
  - 软考
  - 软件设计师-中级
  - DNN
updated: YYYY-MM-DD
---

# {知识域}（DNN）

## {教程小节或主题}

### {知识点名称}

【考点：上午选择题 / 应用技术】

（定义、判断步骤、公式、边界条件和易错点）
```

### 系统架构设计师-高级

按 [chapter-routing.md](chapter-routing.md) 取得章号和章名。文件名使用零补齐章号，例如 `05-软件工程基础知识.md`。

精确小节标题依次来自已有笔记、用户提供的合法教材目录或可靠资料。无法验证小节时使用 `## 未定位到教材小节`，不得虚构 `N.x` 或 `N.x.x`。

新文件结构：

```markdown
---
tags:
  - 软考
  - 系统架构设计师-高级
  - 第 N 章
updated: YYYY-MM-DD
---

# 第 N 章 章名

## N.x 已验证的小节名

### N.x.x 已验证的知识点名称

[考查：综合知识 / 案例分析 / 论文素材]

（定义、判断步骤、边界条件、权衡取舍和易错点）
```

无法验证小节号时改用：

```markdown
## 未定位到教材小节

### {知识点名称}

[考查：综合知识 / 案例分析 / 论文素材]

（定义、判断步骤、边界条件、权衡取舍和易错点）
```

涉及案例时保留“题干关键词 → 专业术语 → 权衡取舍”。

## 错题写法

错题条目的公共字段必须保持以下顺序：

```markdown
### YYYY-MM-DD｜{章节或知识域}｜{题目简述}

- **原题抄写**：
  > {完整题干，含全部选项、子问题、单位和必要图示说明}
- **正确选项**：{答案；非选择题写“正确结论”}
- **简析**：{最短充分推导}
- **我的选项**：{用户答案；未作答写“未作答”；没有信息写“未提供”}
- **其它选项分析**：
  - A：{为什么对或错}
  - B：{为什么对或错}
  - C：{为什么对或错}
  - D：{为什么对或错}
- **知识点链接**：[[Vault 相对路径/文件名#精确标题|知识点名称]]
```

- 非选择题将“其它选项分析”改为“错误过程分析”；用户未提供过程时写“未提供”。
- “我的选项”记录用户原题作答，不能被练习题的选择或字母重排覆盖。若追加诊断记录，放在公共字段之后，区分实际回答、待验证错因与已支持的判断；不把推测写成用户事实。
- 中级条目放入汇总错题本的对应章级 `##` 下；缺少章节时按现有顺序补充。
- 高级条目放入 `系统架构设计师-高级/错题本/NN-章名-错题.md`，按日期倒序排列。
- 题目来源、年份和题号仅在截图或用户文本明确给出时记录；否则写“来源未提供”。

高级错题文件不存在时使用：

```markdown
---
tags:
  - 软考
  - 系统架构设计师-高级
  - 错题本
chapter: "NN-章名"
updated: YYYY-MM-DD
---

# 第 N 章 章名错题本

## 错题记录
```

## Wiki-link 与图示

使用指向精确标题的 Vault 相对 Wiki-link：

```markdown
[[<软考根目录>/软件设计师-中级/07_软件工程#V 模型：测试与开发阶段的对应|V 模型]]
[[<软考根目录>/系统架构设计师-高级/知识点/08-系统质量属性与架构评估#ATAM 方法架构评估实践|ATAM]]
```

- 链接中的文件名不写 `.md`。
- 同名文件写完整 Vault 相对路径。
- `#` 后标题必须与目标文件的实际标题逐字一致。
- 流程、状态或拓扑关系可用 Mermaid；不能无损表达的原图保留图片引用或文字说明。
- 公式统一使用 `$...$` 或 `$$...$$`。

## 写后验证

回读修改后的目标段落并确认：

- 原题和全部选项无遗漏、无凭空补全。
- 正确答案与讲解一致；用户答案没有被猜测。
- 公共字段顺序符合模板，标题层级不跳级。
- Wiki-link 的目标文件存在，锚点与实际标题一致。
- 同一道题只出现一次，既有人工内容和复习状态未被覆盖。
- `updated` 为实际修改日期；没有改动无关文件。

验证后报告各题的写入位置与结果（新增、范围内更新、同题已存在而未改动，或受阻原因）。已通过的检查不因题目数量增加而重复核验无关文件。
