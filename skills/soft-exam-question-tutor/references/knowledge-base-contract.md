## 权威目录与目标

默认知识库根目录为 Vault 内的 `个人资料/笔记/软考/`。用户指定其它根目录时使用该目录，并相应调整 Wiki-link；首次使用先确认目标 Vault，不能依赖作者设备路径。

| 级别 | 知识点目标 | 错题目标 |
|---|---|---|
| 软件设计师-中级 | `软件设计师-中级/知识点/01-计算机组成原理.md` 至 `知识点/12-多媒体基础.md` 的对应章级文件 | `软件设计师-中级/软考-软设-错题本.md` 的对应章节 |
| 系统架构设计师-高级 | `系统架构设计师-高级/知识点/NN-章名.md` | `系统架构设计师-高级/错题本/NN-章名-错题.md` |

中级沿用当前 Vault 已有章级笔记和汇总错题本，不同时写 `17_易错题集.md`。高级从本 Skill 启用后按教程 20 章逐题建档；若存在 `笔记.md` 和 `03_错题与复盘模板.md`，将其作为历史汇总资料保留，不迁移、不删除、不双写。只有用户确认归档且对应章首次出现时，才创建该章文件和必要目录，运行期间不额外批量建空文件；toolkit 初始化可提供预建的知识骨架和空错题本。

## 写入前检查

1. 确认用户已经明确同意归档。
2. 确认考试级别；“两者共有”必须由用户选择目标目录。
3. 读取完整目标文件，检查 frontmatter、章节顺序、现有标题和人工内容；目标尚不存在时，先查看同级目录的命名与格式。
4. 在目标文件和该级别可用的历史汇总文件中，用规范化后的题干关键句与选项搜索是否已有同题；已有时报告命中位置，未经用户另行确认不重复归档。
5. 搜索是否已有知识点标题；目标章级文件内已有时复用最精确的标题，不另造同义标题。

## 知识点写法

### 中级

按 [chapter-routing.md](chapter-routing.md) 选择 D01-D12 文件。已有 `##` 小节时在该小节内补充；没有时在“待补充”之前创建新的 `##` 小节。需要更细粒度锚点时使用 `###`。

新文件只在目标章级文件确实不存在时创建，命名遵循 `知识点/NN-名称.md`，结构如下：

```markdown
---
tags:
  - 软考
  - {知识域}
  - DNN
updated: YYYY-MM-DD
---

# {知识域} (DNN)

## 1. {教程小节或主题}

### {知识点名称}

【考点：上午选择题 / 下午第 X 题】

（定义、判断步骤、公式、边界条件、易错点）
```

### 高级

依据 [architecture-toc.md](architecture-toc.md) 取得准确章名和小节号。知识点文件放在 `系统架构设计师-高级/知识点/`，文件名使用零补齐章号：`NN-章名.md`，例如 `05-软件工程基础知识.md`。文件存在时在对应小节补充；不存在时按以下结构创建：

```markdown
---
tags:
  - 软考
  - 系统架构设计师-高级
  - 第 N 章
updated: YYYY-MM-DD
---

# 第 N 章 章名

## N.x 小节名

### N.x.x 知识点名称

[考查：综合知识 / 案例分析 / 论文素材]

（定义、判断步骤、边界条件、权衡取舍和易错点）
```

若目录只有二级节，知识点可直接置于 `## N.x 小节名` 下；不要虚构三级编号。`笔记.md` 若存在，仅用于查重和理解旧内容，不再作为新题的写入目标。

新增内容标注 `[考查：综合知识 / 案例分析 / 论文素材]`，涉及案例时保留“题干关键词 → 专业术语 → 权衡取舍”。

## 错题写法

错题条目的公共字段必须保持以下顺序：

```markdown
### YYYY-MM-DD｜{章节或知识域}｜{题目简述}

- **原题抄写**：
  > {完整题干，含全部选项、子问题、单位和必要图示说明}
- **正确选项**：{答案；非选择题写“正确结论”}
- **简析**：{最短充分推导}
- **我的选项**：{用户答案；未作答写“未作答”；没有信息写“未提供”}
- **其它选项分析**：
  - A：{为什么对或错}
  - B：{为什么对或错}
  - C：{为什么对或错}
  - D：{为什么对或错}
- **知识点链接**：[[相对路径/文件名#精确标题|知识点名称]]
```

- 非选择题将“其它选项分析”改为“错误过程分析”；若用户未提供过程，写“未提供”。
- 中级条目放入 `软考-软设-错题本.md` 的现有 `## 第 N 章` 下；缺少章节时按现有顺序新建章节标题。
- 高级错题文件放在 `系统架构设计师-高级/错题本/`，文件名为 `NN-章名-错题.md`。文件不存在时按下列最小结构创建，条目按日期倒序放在 `## 错题记录` 下：

```markdown
---
tags:
  - 软考
  - 系统架构设计师-高级
  - 错题本
chapter: "NN-章名"
updated: YYYY-MM-DD
---

# 第 N 章 章名错题本

## 错题记录
```

若存在 `03_错题与复盘模板.md`，可参考其中的合法错因标签，再在公共字段之后追加 `错因标签` 和 `D1/D7/D21` 字段，但不改写该历史模板。
- 题目来源、年份、题号只有在截图或用户文本明确给出时才写；否则写“来源未提供”。

## Wiki-link 与图示

使用指向精确标题的 Vault 相对 Wiki-link，不使用设备绝对路径：

```markdown
[[个人资料/笔记/软考/软件设计师-中级/知识点/07-软件工程#1. V 模型：测试与开发阶段的对应|V 模型]]
[[个人资料/笔记/软考/系统架构设计师-高级/知识点/08-系统质量属性与架构评估#8.3 ATAM 方法架构评估实践|ATAM]]
```

- 链接中的文件名不写 `.md`。
- 同名文件必须写完整 Vault 相对路径。
- 流程、状态或拓扑关系可用 Mermaid；不能无损表达的原图不强制转图。
- 公式统一使用 `$...$` 或 `$$...$$`。

## 写后验证

回读修改后的目标段落并逐项确认：

- 原题与全部选项无遗漏、无凭空补全。
- 正确答案与讲解一致；用户答案没有被猜测。
- 公共字段顺序符合模板，标题层级不跳级。
- Wiki-link 的目标文件存在，`#` 后标题与文件中的实际标题逐字一致。
- 同一道题只出现一次，既有人工内容和复习勾选状态未被覆盖。
- `updated` 为实际修改日期；没有改动无关文件。
