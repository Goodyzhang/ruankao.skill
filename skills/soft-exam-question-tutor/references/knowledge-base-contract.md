# Obsidian 软考知识库写入契约

## 目录

- 根目录与目标
- 写入前检查
- 知识点写法
- 错题写法
- Wiki-link 与图示
- 写后验证

## 根目录与目标

默认知识库根目录为 `个人资料/笔记/软考/`。工作区指令或用户显式指定的 Vault 相对目录优先；不得写入设备绝对路径。

| 级别 | 知识点目标 | 错题目标 |
|---|---|---|
| 软件设计师-中级 | `软件设计师-中级/NN_知识域.md` | `软件设计师-中级/软考-软设-错题本.md` 的对应章节 |
| 系统架构设计师-高级 | `系统架构设计师-高级/知识点/NN-章名.md` | `系统架构设计师-高级/错题本/NN-章名-错题.md` |

优先沿用当前 Vault 的章级笔记、命名和汇总错题本。旧笔记或模板只用于查重与格式参考，不迁移、不删除、不双写。仅在用户确认归档且目标文件不存在时创建必要目录和文件，不批量预建空文件。

## 写入前检查

1. 确认用户已明确同意归档。
2. 确认考试级别；“两者共有”必须由用户选择目标目录。
3. 读取完整目标文件，检查 frontmatter、章节顺序、现有标题和人工内容；目标不存在时先查看同级目录的命名与格式。
4. 用规范化后的题干关键句和选项搜索同题；已有时报告命中位置，未经用户再次确认不重复归档。
5. 搜索已有知识点标题；存在时复用最精确标题，不另造同义标题。
6. 确认正确答案有可靠依据；证据不足时停止归档。

## 知识点写法

### 软件设计师-中级

按 [chapter-routing.md](chapter-routing.md) 选择 D01—D12 知识域。已有小节时在对应位置补充；没有时创建新的 `##` 小节。需要更细粒度锚点时使用 `###`。

新文件只在对应章级文件确实不存在时创建，默认命名为 `NN_名称.md`：

```markdown
---
tags:
  - 软考
  - 软件设计师-中级
  - DNN
updated: YYYY-MM-DD
---

# {知识域}（DNN）

## {教程小节或主题}

### {知识点名称}

【考点：上午选择题 / 应用技术】

（定义、判断步骤、公式、边界条件和易错点）
```

### 系统架构设计师-高级

按 [chapter-routing.md](chapter-routing.md) 取得章号和章名。文件名使用零补齐章号，例如 `05-软件工程基础知识.md`。

精确小节标题依次来自已有笔记、用户提供的合法教材目录或可靠资料。无法验证小节时使用 `## 未定位到教材小节`，不得虚构 `N.x` 或 `N.x.x`。

新文件结构：

```markdown
---
tags:
  - 软考
  - 系统架构设计师-高级
  - 第 N 章
updated: YYYY-MM-DD
---

# 第 N 章 章名

## N.x 已验证的小节名

### N.x.x 已验证的知识点名称

[考查：综合知识 / 案例分析 / 论文素材]

（定义、判断步骤、边界条件、权衡取舍和易错点）
```

无法验证小节号时改用：

```markdown
## 未定位到教材小节

### {知识点名称}

[考查：综合知识 / 案例分析 / 论文素材]

（定义、判断步骤、边界条件、权衡取舍和易错点）
```

涉及案例时保留“题干关键词 → 专业术语 → 权衡取舍”。

## 错题写法

错题条目的公共字段必须保持以下顺序：

```markdown
### YYYY-MM-DD｜{章节或知识域}｜{题目简述}

- **原题抄写**：
  > {完整题干，含全部选项、子问题、单位和必要图示说明}
- **正确选项**：{答案；非选择题写“正确结论”}
- **简析**：{最短充分推导}
- **我的选项**：{用户答案；未作答写“未作答”；没有信息写“未提供”}
- **其它选项分析**：
  - A：{为什么对或错}
  - B：{为什么对或错}
  - C：{为什么对或错}
  - D：{为什么对或错}
- **知识点链接**：[[Vault 相对路径/文件名#精确标题|知识点名称]]
```

- 非选择题将“其它选项分析”改为“错误过程分析”；用户未提供过程时写“未提供”。
- 中级条目放入汇总错题本的对应章级 `##` 下；缺少章节时按现有顺序补充。
- 高级条目放入 `系统架构设计师-高级/错题本/NN-章名-错题.md`，按日期倒序排列。
- 题目来源、年份和题号仅在截图或用户文本明确给出时记录；否则写“来源未提供”。

高级错题文件不存在时使用：

```markdown
---
tags:
  - 软考
  - 系统架构设计师-高级
  - 错题本
chapter: "NN-章名"
updated: YYYY-MM-DD
---

# 第 N 章 章名错题本

## 错题记录
```

## Wiki-link 与图示

使用指向精确标题的 Vault 相对 Wiki-link：

```markdown
[[个人资料/笔记/软考/软件设计师-中级/07_软件工程#V 模型：测试与开发阶段的对应|V 模型]]
[[个人资料/笔记/软考/系统架构设计师-高级/知识点/08-系统质量属性与架构评估#ATAM 方法架构评估实践|ATAM]]
```

- 链接中的文件名不写 `.md`。
- 同名文件写完整 Vault 相对路径。
- `#` 后标题必须与目标文件的实际标题逐字一致。
- 流程、状态或拓扑关系可用 Mermaid；不能无损表达的原图保留图片引用或文字说明。
- 公式统一使用 `$...$` 或 `$$...$$`。

## 写后验证

回读修改后的目标段落并确认：

- 原题和全部选项无遗漏、无凭空补全。
- 正确答案与讲解一致；用户答案没有被猜测。
- 公共字段顺序符合模板，标题层级不跳级。
- Wiki-link 的目标文件存在，锚点与实际标题一致。
- 同一道题只出现一次，既有人工内容和复习状态未被覆盖。
- `updated` 为实际修改日期；没有改动无关文件。
