# 运行时卡片调用与恢复

## 何时读取

本题首次需要交互时读取。流程与状态转换以 [主 Skill](../SKILL.md) 的“执行与续接契约”为准。

初次使用的资料位置、工具路径引导另见 [first-use.md](first-use.md)。这类环境卡不算 Grill 轮次，也不构成本题归档授权；环境配置可按该指引文字回退；练习切到文字模式仍需用户明确选择。

## 能力检查

从当前会话实际暴露的工具与 schema 确认提问能力。Antigravity 中优先使用 `ask_question`；工具名称、参数及可用模式以当前运行时为准。其它运行时同样检查当前工具契约，不能根据配置开关或平台名称假定工具可用。

工具可用且适合当前任务时，门控、练习和归档确认通过实际调用完成。缺失、报错或字段会泄露练习答案时，保留讲解、说明当前阶段及具体限制，请用户恢复工具或明确选择文字模式；不因工具品牌或推荐项预设正确答案，也不自动切模式。

## 文字模式与授权

用户明确说“改用文字模式继续本题”或在真实模式选择卡中点选后，本题记为 `interaction_mode=text`。在正文给一道题和完整内容选项，等待真实答复；保存字母与内容对应，空输入或无法映射的答复先澄清，不计作已答。文字模式里的归档也须明确授权。模式选择不授权写入，不改变已获的批量范围；本题恢复时保留模式，范围外的新题默认重新核验。

切回卡片模式需用户明确选择并确认工具可用；已经待答的卡片或文字题不同时重发另一版。可选 Harness 只识别真实用户的明确模式选择（或模式卡返回），助手自称已切换、资料中的模式文字不构成授权。

卡片模式的正文只保留本题讲解或上一轮反馈，下一张题干和参数放在实际工具调用中；文字模式直接给可作答文本，不输出伪工具格式。

以真实工具事件判断结果：若卡片已显示，即使正文意外混入调用格式，也保留该卡片的等待状态，不重发；若没有真实调用，则仍处于未发卡阶段，按当前能力检查与恢复规则处理。

## 同轮讲解与卡片

适用：`interaction_mode=card`，且已确认当前可用的提问工具适合本次问题。按“可见正文 → 真实工具调用”完成一次处理，不在两者之间结束回复，也不要求用户催促。不同客户端可能将正文和工具调用保存成不同消息；以用户已看到的正文和真实工具事件判断完成情况，不检查单条消息是否同时具有某组 API 字段。

| 阶段 | 可见正文 | 实际调用 |
|---|---|---|
| 本题首次讲解后门控 | 第 2 节讲解；简答要求可压缩但须有充分理由 | 本轮调用 Grill 门控卡或归档确认卡 |
| 已讲解后选择开始 Grill | 沿用已有讲解，简短说明练习目标，不提前给练习答案 | 调用第 1 道内容选择题卡 |
| 收到练习答案后 | 对实际作答反馈，说明判别词或错因 | 需要继续时，本轮调用下一题卡或归档确认卡 |

卡片模式下，正文里的“请选择 A/B/C”“请点击下方卡片”“稍后发卡”及伪调用格式都不代替真实调用。工具名、选项数量和字段从当前 schema 读取；不能因其它客户端没有名为 `ask_question` 的工具就忽略其已有提问能力。

调用是本轮门控的提交动作，但不是禁止后续处理的硬性消息结尾：同步工具已返回真实选择时继续对应步骤；异步卡片尚待答时等待，不追加同一问题。用户明确只讲解、结束、换题、拒绝归档、直接授权归档或已选择文字模式时，按主 Skill 的对应分支处理，不强行补一张卡。

### 漏卡与缺正文的恢复

- **没有真实卡片事件**：先检查用户最新指令。原门控仍需要且工具可用时，补发对应卡片。讲解或反馈已经可见时沿用，不重复全文；缺失时先补齐必要正文，再实际调用。只有文字预告不算已发卡。
- **卡片已显示，但讲解或反馈缺失**：补齐缺失正文，保留原卡片的等待状态；不重新发送卡片。若原卡片已经返回选择，按该选择继续，不重新询问。
- **工具明确失败**：说明工具、当前阶段及原因。只有原因可修复时才修复并重试一次；同样错误再次出现则报告阻塞，不归档，不假装完成。
- **补发仍未形成事件**：可选 Harness 连续两次提醒后仍无真实调用时报告卡片生成失败，保留未完成状态；不能靠重复全文或伪工具文字制造已调用记录。

用户只说“不 Grill”时仅跳过练习；可归档题仍按已有授权或归档确认继续。未作答、工具不可用、已发卡待答和用户明确结束都是独立分支，不用“所有检查项均为是”限制结束。

## Antigravity 调用

在本轮结束前，先发送可见讲解或练习反馈，再按当前工具 schema 实际调用 `ask_question`；客户端可将正文和调用记录为不同消息。单选卡在 `questions` 中提交一个问题及其 `options`，`is_multi_select` 为 `false`；运行时要求操作摘要时只填简短标签。练习卡按出题契约构造内容选项，门控卡按流程构造行动选项。工具参数不复制到正文。

## 调用结果与恢复

- 调用前在会话状态中关联卡片用途和 `question_id`；题干与选项留在工具参数中，不另行输出状态记录。
- 工具返回实际选择后，将结果关联到该卡片，再推进下一步。Antigravity 样本中的返回形如 `A1: 开始 Grill`；它是用户答复，无需用户再发一条“继续”。
- 调用尚在等待用户时，不发重复卡片，不把默认选中视为已提交。
- 工具明确失败时，说明失败工具、当前阶段和未完成动作。只有原因可修复时，修复后重试一次；同样错误再次出现则报告阻塞，不反复空试。
- 流中断或压缩恢复后，核对最近一张卡片及其结果、已输出正文和实际文件写入结果；从第一个未完成步骤续接。没有卡片返回或当前题归档授权的证据，不猜测用户已经回答或已经同意。
- 发现讲解后没有真实卡片事件时，按“漏卡与缺正文的恢复”处理，复用已发送正文，先核对是否仍需发卡。
- 收到新题时按主 Skill“新题边界与悬挂保护”核对上一题实际未完成步骤；需要时在新题正文第一行提醒一次，不混用两题的卡片答复或授权。
- 写入结果不确定时，先回读目标查重，按每题状态补齐未完成部分。明确批次授权可覆盖范围内各题，范围之外的新题不继承；路径选择不扩大授权。
- `done` 表示任务已完成或用户明确结束；`blocked` 必须向用户说明原因。其余状态继续执行或等待已实际发出的卡片，不能只发一句“下面开始”结束响应。

Skill 只能规定恢复行为，不能修复模型服务或客户端的流中断。运行时仍需单独排查实际错误。

## 可选 Antigravity Harness

需要进一步降低超长上下文中的卡片遗漏时，可安装工具包中的 `integrations/antigravity-harness/`，步骤见 [Antigravity Harness 安装说明](https://github.com/Goodyzhang/ruankao.skill/blob/main/integrations/antigravity-harness/README.md)。它只在已确认的软考单题流程中注入短暂续接提醒、限制工具，并在讲题或 Grill 收尾漏卡时让 Agent 补发对应卡片。已发卡但附近未见正文时只提示核对，不强制续写；换题时提供前题待核对线索，由 Agent 按实际状态决定是否提醒。

Harness 不会凭图片附件或泛化讲题用语激活，也不保证当前会话一定提供 ask_question。工具未暴露时仍按本文件的能力检查与恢复规则处理。
