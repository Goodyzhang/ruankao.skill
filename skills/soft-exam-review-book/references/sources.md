# 取材与事实核验

## 定位

先按 [环境发现](environment.md) 确定资料根与科目目录。`个人资料/笔记/软考/<科目>/` 是原工作区的布局示例，只有实际存在且与本任务相符时才采用。教材、笔记和错题可分散在用户指定的位置，不要求使用同样的文件夹名或先安装 Obsidian。

在已确认范围内用 `rg` 或当前环境的文件搜索查科目、书名、章标题和概念，读命中前后文。可识别的命名线索包括 `教材原文/系统架构设计师教程（第2版）.md`、`知识点/NN-章名.md`、`错题本/NN-章名-错题.md`；它们是候选，不是必须创建的目录。正文可来自 Markdown、PDF 或其它可读取资料，按现有工具读取，不把转换格式作为先决条件。

章节归属以本次教材目录为准。若已安装同级 tutor，可选读其 `references/architecture-toc.md` 和 `references/chapter-routing.md`；候选目录明确按 `skill_root/../soft-exam-question-tutor/references/` 解析，其中 `skill_root` 是本 Skill 的 SKILL.md 所在目录。缺少这些文件不阻塞独立使用，也不虚构其中内容。二级节与三级小节分开：第 2 版的 2.5 是“第五节 计算机网络”，2.5.4 是“组网技术”；其它版本据实际目录核验。记录教材版本、印刷页码/标记及文章知识组对应范围。

## 每节五层材料

| 顺序 | 检查范围 | 怎样影响作品 |
|---|---|---|
| Tier 1 | 本节所有错题与真实作答记录 | 找具体误解、对照条件、重点深度 |
| Tier 2 | 可取得的历年真题及可靠解析 | 确认考法、术语、边界；不得从少量命中估计完整考频 |
| Tier 3 | 其它章节含本知识点的综合错题 | 显示知识怎样组合，跨节题可引用同一身份 |
| Tier 4 | 案例分析、论文等下午题知识 | 将识别转为解释、设计取舍；无项目事实不得编造案例成绩 |
| Tier 5 | 软件设计师等相邻科目 | 建立已学内容的连接，标明科目与要求差异 |

先读教材与本节知识点，再遍历五层。每层简记检索范围、实际命中、用途、缺口；“搜索过”不能写成“全部覆盖”。建立一张人工知识覆盖表：教材位置 → 知识组 → 误解/判别条件 → 文章/图片/自测位置。

完整性优先指知识的完整性。某层题源缺失时联网补知识，而非反复等待用户上传题目。题干/选项残缺可用作检索线索，不复原成“原题”；另写练习就标成自编或改编。

## 真正的错误次数

以“具体考点＋独立作答事件”计数，保存来源定位。一次原题错误后同一条记录的解释、转录、跨节引用均是同一事件；Grill 正确回答与轮数不算新错误。若不同记录是同一次错误的复制，合并；证据不足则记“已确认 N 次，另有待核对记录”。

至少三次已确认独立错误，或用户明确点名，才将该组标为必须详讲。数量不足仍可因概念复杂深入解释，但不能声称达到重复错误门槛。页面自测记录不擅自变成原错题本里的真实考试错误。

## 补充资料与冲突

- 精确搜概念、模型/标准版本、区别与反例，优先规范原文、官方文档、出版社/作者、相关领域第一方技术说明；搜索摘要只用于导航。
- 尾部用可访问的标题链接列来源，制作记录写本地位置/版本/检索日期与采用结论。联网补充的内容与本地教材观点可区分。
- 教材/题库适用口径与工程规范版本不同则说明差异，不能套一个新标准改掉所有旧题名称。例：综合布线“六个子系统”的命名体系可能不同；端口题默认口径与 TLS 条件须分开。
- 旧笔记可能含模型过度断言，须核验“永远”“必定”“法定”“只要”等条件。遇到主干冲突查原始依据，尚未解决的结论暂不进入图与答案，继续其它已确认内容。
- 保存少量必要摘录/自己的摘要，遵守来源版权。作者博客是讲解方法参考，不自动成为协议、标准或题目答案的证据。
