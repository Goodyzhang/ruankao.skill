# 博客讲法与教学品味

## 从一个真实困难开始

先用一句话写出读者会在哪一步判断错。例如“把返回邮件的方向认成主动连接方向”，比“掌握 POP3”更能决定文章与图的内容。选择能呈现这一困难的最小完整情境；开篇给读者方向，中间展开机制，结尾用同一情境检验理解。

可以沿用“判别线索 → 因果链 → 改变条件的反例 → 迁移”的讲法，不启动单题 Gate、Grill 或归档程序。若已安装 tutor 且其 `references/grill-question-design.md` 实际存在，可按需借用错因设计方法；同级安装时按 `skill_root/../soft-exam-question-tutor/references/grill-question-design.md` 定位，`skill_root` 是本 Skill 的 SKILL.md 所在目录。没有 tutor 时依照本文件也能独立完成教学设计，不为此要求安装或虚构读过它。

让新术语在开始发挥作用时出现。先发生“收件人离线，信需要有地方等”，再解释服务器暂存；先发生“换到平板还想看到已读”，再引入 IMAP。首次引入必要缩写时展开英文名称，但名称不能替代机制解释。

## 选择讲法，而非填模板

| 需要理解的关系 | 可用表现 | 关键问题 |
|---|---|---|
| 相似名称与分类 | 同场景位置图、同尺度对照、边界近景 | 换掉哪个条件，类别才会变？ |
| 层次与组成 | 等宽分层、拆解图、树图 | 位置表示职责、包含关系还是先后？ |
| 过程与双方消息 | 时序图、连续分镜、状态图 | 谁先行动，对象/数据到哪了？ |
| 计算 | 数值贯穿的步骤漫画、时空图 | 这一行为何能从上一行推出，单位是什么？ |
| 权衡、算法比较 | 保持任务相同，只改变策略/条件 | 哪个指标改变，代价落在哪里？ |

一个组可以组合多种关系。知识组按共同误解、共同机制或共同考法划分，不把每个名词各拆一组，也不把整个网络章塞进一个组。

对报菜名考点先找统一坐标：地点、输入输出、责任、时间、约束。做必要联网研究找区别和同义表述，再设计“一张图图解”；不要先把名称贴满画布再写解释。

对计算例子先独立算出正确结果和假设，再安排镜头。数字/变量在所有图格、公式、题目保持同一身份；类比只帮助理解，不能代替公式的条件。不要把“题目选项里没有结果”当作随意换模型的规则。

## 正文与图片的分工

正文解释为什么，图提供位置、动作、数量与变化。图前建立观察任务，图后解决真正的疑点，避免每图都用“看下面这张图”报幕和逐字朗读所有标签。

同一次比较保留相同对象与环境。SMTP→POP3 的例子沿同一封“去看海”的邀请：服务器暂存、客户端取回、用户阅读三个状态明确；照片引出 MIME，跨设备状态引出 IMAP。不要每讲一个术语重新换世界观。

可以生动、详细，细节必须帮助理解或记忆。删除假起兴、夸张断言、励志标语、每段收金句、反复“不是……而是……”。角色可追问、指认或演示，不必每格出场。版式和分镜可变，保证阅读顺序清楚。

速查另存精确术语、题干判别词、边界与必要公式，避免浓缩成另一篇长文。自测让读者先判断，再给解释；题目须改变关键条件，不能只把正文某句话挖空。

## 委托 Gemini 时

提供：读者与目标、核验后的事实及限制、真实误解、可用图位/人物、前一段情境、期望声线。先让它提出少量不同讲法并说明取舍，主编辑选择后展开；小组很明确时可一次给方向和初稿。不要预填一排必须填满的标题。

声线参照：
> 在写信软件里打下“明天一起去看海吧！”，点击发送。这时，收件人的平板或许还没联网。那封橙色信封会在哪里等他？等他开机联网，又是谁主动去找谁，把信拿回来？

重点是问题来自场景真实缺口。无需反复复制“去看海”、问句开头或邮件题的结构。审稿时追问：删掉这段是否丢失因果？读者能否解释一个反例？只看图片能否复述主线？文字与图同时看有无多余重复？

## 作者案例（已读，2026-10-03）

- [Bartosz Ciechanowski：GPS](https://ciechanow.ski/gps/)：从距离约束到飞行时间，再加入时钟误差，新概念解决新的具体困难。适合渐进计算与模型；不照搬长篇铺垫。
- [Red Blob Games：A* Introduction](https://www.redblobgames.com/pathfinding/a-star/introduction.html)：保持地图任务一致，比较步数、代价与启发式；交互用于改变条件并预测结果。端口记忆不必做模拟器。
- [Julia Evans：DNS propagation is caches expiring](https://jvns.ca/blog/2021/12/06/dns-doesn-t-propagate/)：由改记录后仍见旧结果的困惑建立缓存模型，改变查询时序解释负缓存。借鉴辨别误解，不搬历史服务商现象作今日规范。
- [Google Technical Writing：Illustrating](https://developers.google.com/tech-writing/two/illustrations)、[Diátaxis：Explanation](https://diataxis.fr/explanation/)：让插图支持明确结论，说明原因与上下文，查表内容另有入口。

这些是方法参照，不复制其素材/代码。若使用者已有认可样章，优先读用户给出的实际位置。可参考已认可的 [SMTP／POP3 在线样章](https://goodyzhang.github.io/ruankao.skill/demo/smtp-pop3/)；toolkit 发布包也提供 `docs/demo/smtp-pop3/index.html` 及离线素材。样章只是讲法参考，不是其它机器必须具备的运行依赖。没有样章时，上述声线与教学标准仍可独立使用。
