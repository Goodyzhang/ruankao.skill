# 分镜、生图与审图

## 先确定图要证明什么

每个知识组强烈推荐至少一张 imagen 图覆盖，多个关系紧密的组可共用图。不规定统一张数；复杂考点可以多画，不能靠缩小字体把一本笔记塞进海报。给每张图写一句学习目标和最容易画错的一项。

核心流程、计算与中文密集漫画用内置 imagegen。少文字辅助黑板/局部示意可用 Grok Build。Mermaid 表达结构、流程或时间关系，每教材小节至少一张，保留 `.mmd` 并渲染本地 SVG；若尚未渲染只能标待完成，不能展示源码冒充成图。

## 角色与画面连续性

内置生图默认 DeepSeek 鲸鱼娘：2.5 头身、蓝发渐变青色、蓝眼、鲸鳍耳、白色女仆头饰、蓝白服饰/围裙、可见时一条分叉鲸尾。参考 [已认可人物图](../assets/characters/whale-reference.png)，仅取角色和风格，不能把参考图上的知识复制到新图。先实际看参考图，再把它作为角色参考传给生图工具。

Grok 辅助图可以用 Ani：金发双马尾、黑色蝴蝶结、蓝眼、端正黑色服装，教学同人形象。不称为统一官方吉祥物。人物是否出现由解释需要决定，不能盖住数据、公式或箭头。

同篇对象颜色、形状、命名与位置保持一致；角色的职业身份与网络客户端/服务端角色不能混为一谈。每格至少推进一个动作、条件、判断或结果。上下/左右位置须确有语义，分类树不画成时间线。

## 提示词最小要素

写明用途与桌面/平板阅读、图的结论、面板顺序、必须逐字保留的标签、关键关系、角色、不可变项与最可能犯的错误。区别“编辑目标”“人物参考”“布局参考”。不用无关风格名填满提示词。

例如请求/返回图：指定服务器左、客户端右，请求从右指左，内容从左指右，并用短标签说明；颜色只作辅助。并列方案不按步骤编号，不画连接两方案的流程箭头。OSI 七层可等宽排列，避免梯形面积暗示重要性。

生成后复制最终采用图到成品本地 assets，保持可复现提示词与来源/修订记录。内置生成与编辑使用现有 imagegen Skill；不使用脚本画一个占位图替代用户要求的生成漫画。

## 每次都看图

1. 中文是否清楚、协议/变量有无拼错、数字和单位是否正确？
2. 层级、对象、箭头两端、请求与内容方向、状态与动作是否符合事实？
3. 同一人物/设备是否延续，是否多出手臂、尾巴或身份错位？
4. 图片是否真的帮助理解；有无模型自行添加的口号、重复小字、无意义对话？

发现错误时只改具体问题，保留已核验部分，修后重新看图。连续两次修订无效，简化标签、拆图或重构；Grok 图可退回内置生成，但不能因此削弱关键知识。不要以工具返回“已修复”代替审图，也不要用 CSS 遮罩掩盖错误文字。

独立审图代理需要实际图像与事实要求，不能只看到主代理评价。事实未通过的图不接入正文；艺术偏好仍交用户审阅。
