# 经典案例分析：物流企业库存管理系统用例建模

## 1. 案例背景与需求陈述

某软件公司拟为物流企业开发一套库存管理系统，该系统的部分需求陈述如下：

1. 库存管理系统主要包括货物入库管理、货物出库管理、仓库管理、统计报表和系统管理等功能；
2. 库存管理系统的用户包括仓库管理员、仓库经理和系统管理员，用户必须在注册后才能使用系统功能；用户可以选择使用邮件注册或电话注册。
3. 仓库管理员在进行出入库操作前必须先登录；仓库经理可以通过系统查看统计报表，如果前一个月的报表未生成，则系统自动生成统计报表，否则直接显示。
4. 系统管理员可以在系统中设置仓库温度范围，当仓库内温度超过最高值或者低于最低值时，系统自动调用温控管理操作，连接温度调节系统进行制冷或加热。
5. 仓库管理功能要求每个月 1 日零点对前一个月货物入库和出库记录进行数据汇总操作。项目组决定构造用例模型以描述系统需求。

## 2. 试题问题与标准答案

### 【问题 1】（6分）
> 用例建模的首要任务是识别系统中的参与者。请根据题目中所描述的需求，识别出系统中有哪些参与者？

#### 破题思路与采分点
参与者（Actor）是指**存在于被建模系统外部、直接与系统交互并获得有价值结果的外部实体**。在识别参与者时必须进行三维无死角排查：
- **维度一：操作人员角色**（直接与系统 UI 交互的不同业务岗位）；
- **维度二：外部系统 / 硬件接口**（系统必须与之通信、调用其服务的第三方系统或外设）；
- **维度三：时间 / 外部时钟**（由时间流逝自动触发的定时批处理任务的事件发起者）。

#### 满分答案
根据题目需求，系统中的参与者包括以下三类共 5 个：
1. **业务操作人员（角色）**：
   - **仓库管理员**（负责执行出入库操作）
   - **仓库经理**（负责查看统计报表）
   - **系统管理员**（负责系统管理与设置仓库温度范围）
2. **外部系统 / 硬件实体**：
   - **温度调节系统**（当温度超出安全阈值时，由系统调用以执行物理制冷或加热的外部系统）
3. **定时触发源 / 外部时钟**：
   - **系统时钟 / 时间（Time / Clock）**（每个月 1 日零点定时自动触发月度数据汇总操作的事件源）

> ❌ **常见失分陷阱**：仅写出“仓库管理员、仓库经理、系统管理员”三个人类用户，遗漏了“温度调节系统”与“系统时钟”，将被扣除 3 分！

### 【问题 2】（7分）
> 用例建模的主要工作是书写用例规约。用例规约通常包括哪几部分内容？

#### 破题思路与采分点
用例图仅提供了系统的黑盒总览视图，无法表达交互细节与业务逻辑。**用例规约（Use Case Specification，又称用例描述）**是用自然语言对单个用例内部交互过程的标准化规格说明文档。

#### 满分答案
一份标准的用例规约通常包含以下 7 个核心组成部分：

1. **用例名称（Use Case Name）**：动宾短语，唯一标识该用例（如“货物入库”）。
2. **简要说明（Brief Description）**：简述用例的业务作用、目标与核心价值。
3. **参与者（Actors）**：发起该用例的主参与者，以及协同交互的次参与者或外部系统。
4. **前置条件（Pre-conditions）**：用例开始执行前，系统必须满足的约束状态（如“操作员已成功登录系统”）。
5. **事件流（Flow of Events，核心部分）**：
   - **基本事件流（Basic Flow）**：理想情况下，参与者与系统之间顺利执行的主路径（主成功场景）。
   - **备选事件流（Alternative Flow）**：发生分支条件、特定可选操作或异常错误时的备用交互路径。
6. **后置条件（Post-conditions）**：用例成功执行完毕后，系统达到的稳定状态或产生的持久化业务结果（如“库存数量更新，生成正式出库单据”）。
7. **特殊需求 / 补充约束（Special Requirements）**：与该用例直接关联的非功能性需求（如响应时间、安全性审计、并发性能等）。

### 【问题 3】（12分）
> 建立了用例模型后，可以利用用例之间的关系调整用例模型，用例之间的关系包括哪几种？对于每种关系，请根据题目中所描述的需求分别给出一组用例。

#### 破题思路与模型架构图
调整用例模型共涉及三种核心关系：**包含关系（Include）**、**扩展关系（Extend）**、**泛化关系（Generalization）**。

```text
       ┌─────────────────────────────────────────────────────────────┐
       │                     用例关系模型架构图                       │
       └─────────────────────────────────────────────────────────────┘

       【泛化关系】                  【包含关系】                   【扩展关系】
     (一般 ──► 特殊)              (基础 ──► 公共)               (扩展 ──► 基础)

       ┌──────────┐              ┌──────────┐                  ┌──────────┐
       │ 用户注册  │              │ 货物入库  │                  │ 查看统计 │
       └────▲─────┘              └────┬─────┘                  │   报表   │
            │                         │                        └────▲─────┘
     ┌──────┴──────┐                  │ <<include>>                 │ <<extend>>
     │             │                  ▼                             │ (报表未生成)
┌─────────┐   ┌─────────┐        ┌──────────┐                  ┌────┴─────┐
│ 邮件注册 │   │ 电话注册 │        │   登录   │                  │ 自动生成 │
└─────────┘   └─────────┘        └──────────┘                  │ 统计报表 │
                                                               └──────────┘
```

#### 满分答案

用例之间的关系包括以下 3 种：

#### 1. 包含关系（Include）
- **概念定义**：基础用例在执行过程中，**必须、无条件地**调用被包含用例所封装的行为。包含关系用于提炼多个用例中共有的公共行为逻辑，实现逻辑复用并避免冗余。UML 中使用带 `<<include>>` 构造型的虚线箭头由基础用例指向被包含用例。
- **题目对应需求**：需求（3）明确指出“仓库管理员在进行出入库操作前必须先登录”。
- **用例组实例**：
  - 基础用例：**货物入库**（或“货物出库”）
  - 被包含用例：**登录**
  - 关系表达：**“货物入库”包含（`<<include>>`）“登录”**；**“货物出库”包含（`<<include>>`）“登录”**。

#### 2. 扩展关系（Extend）
- **概念定义**：扩展用例为基础用例增加额外的可选行为或异常处理逻辑。扩展用例**只有在满足特定扩展条件并在基础用例的扩展点（Extension Point）上才会被触发执行**；若条件不满足，基础用例仍可独立正常结束。UML 中使用带 `<<extend>>` 构造型的虚线箭头由扩展用例指向基础用例。
- **题目对应需求**：需求（3）指出“仓库经理可以通过系统查看统计报表，如果前一个月的报表未生成，则系统自动生成统计报表，否则直接显示”。
- **用例组实例**：
  - 基础用例：**查看统计报表**
  - 扩展用例：**自动生成统计报表**
  - 扩展条件：**前一个月的报表未生成**
  - 关系表达：**“自动生成统计报表”扩展（`<<extend>>`）“查看统计报表”**。

#### 3. 泛化关系（Generalization）
- **概念定义**：一般用例与特殊用例之间的父子继承关系。子用例（特殊用例）继承父用例（一般用例）的行为与业务规则，并在此基础上提供特殊的实现方式或特化行为。UML 中使用带空心三角箭头的实线由子用例指向父用例。
- **题目对应需求**：需求（2）指出“用户必须在注册后才能使用系统功能；用户可以选择使用邮件注册或电话注册”。
- **用例组实例**：
  - 一般用例（父用例）：**用户注册**（或“注册”）
  - 特殊用例（子用例）：**邮件注册**、**电话注册**
  - 关系表达：**“邮件注册”与“电话注册”泛化自（继承自）“用户注册”**。
  - *备选用例组*：特殊用例“制冷”和“加热”泛化自一般用例“温控管理/温度调节”。

## 3. 架构师案例实战答题方法学

1. **三维排查参与者法则**：
   - 凡有自动化、批处理、月结、日清 $\to$ 必有 **系统时钟（Time / Clock）**；
   - 凡有外设联动、硬件控制、短信/支付/第三方云接口 $\to$ 必有 **外部系统 / 硬件实体**。
2. **包含与扩展方向判定铁律**：
   - 包含关系（Include）：基础用例主导，**主指向辅**（`基础用例 ──► 被包含用例`）；
   - 扩展关系（Extend）：扩展用例为辅，**辅指向主**（`扩展用例 ──► 基础用例`，带有特定 Extension Point 和条件）。
