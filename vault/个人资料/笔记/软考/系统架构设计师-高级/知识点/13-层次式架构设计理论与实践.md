### 13.2.1 表现层设计模式

#### MVC 架构模式：三组件职责与归类判别 ⭐⭐

[考查：综合知识 / 案例分析（元素归类填表）]

- **模型（Model）**：封装与业务逻辑相关的**数据及对数据的处理方法**；可直接访问数据库；**不依赖 View 和 Controller**（不关心如何显示、如何被操作）；数据变化通过刷新机制公布，View 须事先在 Model 上注册才能感知改变。
- **视图（View）**：实现数据**有目的的显示**；View 中**一般没有程序上的逻辑**；为实现刷新需访问所监视的 Model。
- **控制器（Controller）**：起**不同层面间的组织作用**，控制应用程序流程；**处理事件并作出响应**——"事件"包括用户行为和 Model 上的改变。
- **归类判别口诀**：**名词 → Model（数据/工件/角色），纯展示 → View（图/报表），动词 → Controller（操作/动作）；活动、事件类条目三类不归**（典型干扰项）。
- **应用实例**（Scrum 项目管理系统案例）：Model = Project、Product Backlog、用户故事、用户、Task、Sprint、产品负责人、Sprint Backlog；View = Sprint 燃尽图、Release 燃尽图；Controller = 新建项目、估算任务预计完成时间；干扰项 = Sprint 回顾会议、交付产品增量（活动/事件）。
- **易错点**："用户 / 产品负责人"是角色**数据**归 Model，不因为是"人"就归 Controller。

### 13.4.3 ORM、Hibernate 与 CMP2.0 设计思想

[考查：综合知识（定义分类、手写 SQL 辨析）/ 案例分析 / 论文素材]

#### 持久层 ORM 框架选型：全自动 ORM vs 半自动 ORM（MyBatis vs Hibernate / EF） ⭐⭐⭐

- **ORM 核心概念**：对象-关系映射（Object-Relational Mapping），解决面向对象模型与关系型数据库二维表之间的阻抗不匹配（Impedance Mismatch）。
- **全自动 ORM vs 半自动 ORM 对比模型**：

| 特性维度 | 全自动 ORM（Hibernate / JPA / Entity Framework / JDO） | 半自动 ORM（MyBatis / 原 iBatis） |
|---|---|---|
| **核心驱动思想** | **以对象为中心（Object-Centric）** | **以 SQL 为中心（SQL-Centric / SQL Mapper）** |
| **SQL 生成机制** | 框架引擎根据对象映射关系**全自动动态生成**，屏蔽底层 SQL | **必须由程序员手工编写原生 SQL**（XML 或注解维护） |
| **查询抽象语言** | HQL（Hibernate Query Language）、LINQ（.NET EF） | 原生 SQL（支持特定数据库专属函数与语法特性） |
| **数据库独立性** | **高**（框架通过各数据库 Dialect 方言屏蔽语法差异） | **较低**（SQL 绑定具体方言，跨库迁移需改写 SQL） |
| **执行计划控制力** | **弱**（黑盒生成，深层多表关联难以精细优化，易产生 N+1 查询） | **极强**（手写 SQL，可精确控制执行计划、索引 Hint 与覆盖索引） |
| **DBA 审计友好度** | **差**（动态生成难以静态分析与审查） | **极高**（SQL 集中写在 XML 文件中，DBA 可独立走查与压测） |
| **典型适用场景** | 内部企业管理系统（ERP/OA）、中小型项目、强调面向对象与快速 CRUD 开发 | 大型互联网平台、高并发电商交易、复杂报表多表联查、强性能调优诉求系统 |

- **口诀速记**：**“全自动操作实体树，Hiber、EF 与 JDO；唯有 MyBatis 半自动，Mapper 手写 SQL 留。”**
- **高频设陷点**：
  - ❌ 误将 Entity Framework 当做需要手写 SQL 的框架 $\rightarrow$ EF 是微软 .NET 的官方旗舰全自动 ORM（等价于 Java 界的 Hibernate），LINQ 操作对象，SQL 全自动生成。
  - ❌ 误以为 MyBatis 只能简单映射 $\rightarrow$ MyBatis 优势在于 SQL 与代码解耦（集中管理），对底层控制度最高。
- **真题与论文锚点**：
  - 2015 年下半年系统架构设计师下午案例题二（数据访问层 Hibernate vs iBatis 选型对比）。
  - 2016 年下半年系统架构设计师论文题（《论从 Hibernate 到 MyBatis 的 ORM 架构演进》）。
