# 数据库系统 (D05)

> 上午题约 6-8 分 + 下午第 2 题（数据库设计）

## 1. 函数依赖

[考点] 上午选择题 | [基础]

| 概念 | 说明 |
|------|------|
| **函数依赖** X→Y | X 确定后 Y 唯一确定 |
| **完全函数依赖** | X 的任何真子集都不能单独→Y |
| **部分函数依赖** | X 的某个真子集也能→Y（不满足 2NF 的原因） |
| **传递函数依赖** X→Y, Y→Z | X 先决定 Y，Y 再决定 Z（不满足 3NF 的原因） |

## 2. 范式判断

[考点] 上午选择题 | [高频]

| 范式 | 条件 | 消除什么 |
|------|------|---------|
| **1NF** | 属性不可再分（原子性） | — |
| **2NF** | 满足 1NF + 消除部分函数依赖 | 非主属性对码的部分依赖 |
| **3NF** | 满足 2NF + 消除传递函数依赖 | 非主属性对码的传递依赖 |
| **BCNF** | 满足 3NF + 消除主属性对码的部分/传递依赖 | 所有决定因素都是候选码 |

### 判断步骤
1. 找出所有候选关键字
2. 1NF：所有属性都是原子的？ → 一般是
3. 2NF：非主属性完全依赖于候选码？ → 没有"码的子集→非主属性"
4. 3NF：非主属性不传递依赖于候选码？ → 没有"非主→非主"
5. BCNF：所有函数依赖的决定因素都包含候选码？

## 3. 候选关键字推导

[考点] 上午选择题 | [高频]

### 方法：求属性闭包
1. 从候选属性集 X 出发
2. 反复应用函数依赖，扩展 X 的闭包 $X^+$
3. 直到 $X^+$ 包含全部属性 → X 是候选码
4. 如果不行，尝试扩展 X

## 4. Armstrong 公理

[考点] 上午选择题 | [中频]

| 公理 | 形式 |
|------|------|
| **自反** | 若 $Y \subseteq X$，则 $X \to Y$ |
| **增广** | 若 $X \to Y$，则 $XZ \to YZ$ |
| **传递** | 若 $X \to Y$，$Y \to Z$，则 $X \to Z$ |
| **合并** | 若 $X \to Y$，$X \to Z$，则 $X \to YZ$ |
| **分解** | 若 $X \to YZ$，则 $X \to Y$，$X \to Z$ |
| **伪传递** | 若 $X \to Y$，$WY \to Z$，则 $XW \to Z$ |

## 5. 无损联接判定

[考点] 上午选择题 | [高频]

**二元分解** $R = R_1 \cup R_2$：
- 若 $R_1 \cap R_2 \to R_1$ **或** $R_1 \cap R_2 \to R_2$，则无损

**表格法**（多于二元）：
- 构造初始表，通过函数依赖反复填符号
- 若某行全为 a（即全为原始属性），则无损

## 6. 下午第 2 题：数据库设计

题型结构：
1. **补充 ER 图**：识别实体、联系、属性
2. **关系模式转换**：ER → 关系模式
3. **SQL 编写**：简单的增删改查
4. **范式分析**：指出设计问题、规范化

### ER 图要素
- **实体**：矩形
- **联系**：菱形（1:1 / 1:N / M:N）
- **属性**：椭圆

### ER → 关系模式转换规则
- 实体 → 一张表
- 1:1 联系 → 任选一端加入另一端主键
- 1:N 联系 → N 端加入 1 端主键
- M:N 联系 → **单独一张表**（两端主键 + 联系属性）
