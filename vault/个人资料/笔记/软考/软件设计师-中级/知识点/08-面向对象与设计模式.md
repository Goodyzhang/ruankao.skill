# 面向对象与设计模式 (D08)

> 上午题约 5-7 分 + 下午第 5/6 题（Java 设计模式代码填空）

## 1. 面向对象基础

[考点] 上午选择题 | [基础]

### 三大特性
| 特性 | Java 关键字 | Python | 一句话 |
|------|-----------|--------|--------|
| **封装** | `private`/`protected`/`public` | `_`/`__` 约定 | 隐藏内部细节 |
| **继承** | `extends` | `class Child(Parent)` | 子承父业 |
| **多态** | `@Override` + 父类引用指向子类对象 | 鸭子类型 | 同一接口，不同表现 |

### 关键语法对照（软考下午第5/6题必考）
| 场景 | Java 写法 | 填空要点 |
|------|----------|---------|
| 抽象类 | `abstract class A` | 不能 `new`，可以有普通方法 |
| 抽象方法 | `abstract void draw();` | **无方法体**，分号结尾 |
| 接口 | `interface A` | 方法默认 `public abstract` |
| 实现接口 | `class B implements A` | 不是 `extends`！ |
| 继承父类 | `class B extends A` | 单继承 |
| 同时实现 | `class B extends A implements C` | `extends` 在前 |
| 调用父类 | `super.method()` | 构造器中 `super()` 必须第一行 |
| 自身引用 | `this.field` | 区分参数和成员 |

## 2. 设计模式分类总览（23 种 GoF）

### 创建型（5种）：怎么"new"对象

| 模式 | 一句话 | 软考频率 |
|------|--------|---------|
| **单例** (Singleton) | 全局只有一个实例 | 🔥 必考 |
| **工厂方法** (Factory Method) | 让子类决定创建什么 | 🔥 高频 |
| **抽象工厂** (Abstract Factory) | 创建一族相关对象 | ⚠️ 中频 |
| **生成器** (Builder) | 分步构建复杂对象 | ⚠️ 中频 |
| **原型** (Prototype) | 克隆已有对象 | 🟢 低频 |

### 结构型（7种）：怎么组装类和对象

| 模式 | 一句话 | 软考频率 |
|------|--------|---------|
| **适配器** (Adapter) | 转换接口：两口插座→三口 | 🔥 高频 |
| **桥接** (Bridge) | 抽象与实现分离（遥控器vs电视） | 🔥 高频 |
| **组合** (Composite) | 树形结构：文件夹-文件 | ⚠️ 中频 |
| **装饰器** (Decorator) | 动态加功能：咖啡+牛奶+糖 | 🔥 高频 |
| **代理** (Proxy) | 替身对象：律师代理委托人 | 🔥 高频 |
| **外观** (Facade) | 统一入口：总开关 | ⚠️ 中频 |
| **享元** (Flyweight) | 共享不变部分（字符池） | 🟢 低频 |

#### 桥接模式：定义、角色与易混点

**定义**：Bridge 将抽象部分与实现部分分离，使两者可以独立变化。它是结构型模式，适合“图形种类”和“绘图实现”这类两个维度都要扩展的场景。

| UML 角色 | 图形绘制示例 |
|---|---|
| Abstraction | Shape，位于菱形端并持有 Implementor 引用 |
| RefinedAbstraction | Rectangle、Circle |
| Implementor | Drawing，位于菱形箭头指向端 |
| ConcreteImplementor | V1Drawing、V2Drawing |

**速判**：找菱形，菱形端是 Abstraction，箭头指向端是 Implementor；两棵继承树独立扩展。

**易混点**：

- Adapter：转换不兼容接口。
- Decorator：在同一 Component 树上动态加职责。
- Strategy：替换算法族。

### 行为型（11种）：怎么分工协作

| 模式 | 一句话 | 软考频率 |
|------|--------|---------|
| **策略** (Strategy) | 算法可切换：支付方式选择 | 🔥 高频 |

## 3. 下午第 5/6 题解题策略

### 题目构成
1. **类图**：展示模式结构（类、接口、继承/实现关系、关联/聚合）
2. **说明文字**：描述模式意图和角色
3. **代码**：C++ 和 Java 两个版本，留 5-6 个空
4. **填空**：填写类名、方法名、关键字

### 解题三步法
1. **识别模式**：看类图结构 → 对照 23 种模式特征 → 确定是哪种
2. **映射角色**：把类图中的每个类映射到该模式的标准角色（Product/Creator/Strategy/Context 等）
3. **填空**：
   - 类名/接口名 → 对照类图直接填
   - 方法名 → 对照模式标准方法名（`operation()`、`factoryMethod()`、`execute()` 等）
   - 关键字 → `abstract`、`extends`、`implements`、`new`、`super`、`this`

### 高频填空模式
```java
// 单例 —— 必考关键字：private, static, new, null
private static Singleton instance;
private Singleton() {}
public static Singleton getInstance() {
    if (instance == null)
        instance = new Singleton();
    return instance;
}

// 工厂方法 —— 必考：abstract, extends, new
abstract class Creator {
    public abstract Product factoryMethod();
}
class ConcreteCreator extends Creator {
    public Product factoryMethod() {
        return new ConcreteProduct();
    }
}

// 策略 —— 必考：interface, implements
interface Strategy { void algorithm(); }
class Context {
    private Strategy strategy;
    public void setStrategy(Strategy s) { this.strategy = s; }
}

// 装饰器 —— 必考：extends, super
class Decorator extends Component {
    protected Component component;
    public Decorator(Component c) { this.component = c; }
    public void operation() { component.operation(); }
}

// 模板方法 —— 必考：abstract, final
abstract class AbstractClass {
    public final void templateMethod() {  // final 防止子类修改
        step1();
        step2();
    }
    protected abstract void step1();
    protected abstract void step2();
}
```
