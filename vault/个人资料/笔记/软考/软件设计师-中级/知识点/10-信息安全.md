# 信息安全 (D10)

> 上午题约 2-3 分

## 1. 数字证书与 CA

[考点] 上午选择题 | [中频]

### 数字证书是什么？
数字证书 = 持有者信息 + 公钥 + **CA 的数字签名**

### CA 如何签发证书？
1. 用户提交身份信息 + 公钥
2. CA 验证用户身份
3. CA 用 **自己的私钥** 对用户信息+公钥做签名（加密摘要）
4. 生成数字证书

### 浏览器如何验证证书？
1. 浏览器拿到证书
2. 用 **CA 的公钥**（预装在浏览器中）解密签名 → 得到摘要1
3. 自己计算证书内容的摘要 → 得摘要2
4. 摘要1 == 摘要2 → 证书有效 ✅

> **关键**：CA 用**私钥**签名，客户端用 CA **公钥**验证。这是非对称加密的经典应用。

## 2. 对称加密 vs 非对称加密

[考点] 上午选择题 | [基础]

| 对比 | 对称加密 | 非对称加密 |
|------|---------|-----------|
| 密钥 | 同一个密钥加解密 | 公钥+私钥（配对） |
| 速度 | **快** | **慢**（慢 100-1000 倍） |
| 用途 | 加密大量数据 | 密钥交换、数字签名 |
| 代表算法 | **DES** / 3DES / **AES** | **RSA** / ECC |
| 密钥分发 | 需要安全通道 | 公钥可公开 |

> **软考套路**：实际中两者结合使用——用 **RSA 加密 AES 的密钥**，用 **AES 加密实际数据**。

## 3. 数字签名

[考点] 上午选择题 | [中频]

### 签名过程
1. 发送方对消息做哈希得摘要
2. 用 **发送方的私钥** 加密摘要 → 数字签名
3. 消息 + 数字签名 → 发送

### 验证过程
1. 接收方用 **发送方的公钥** 解密签名 → 得摘要1
2. 对收到的消息做同样的哈希 → 得摘要2
3. 摘要1 == 摘要2 → 两个保障：
   - ✅ **完整性**：消息没被篡改
   - ✅ **不可否认性**：确实是发送方发的

### 数字签名 vs 数字证书
| | 数字签名 | 数字证书 |
|------|---------|---------|
| 作用 | 防篡改、防抵赖 | **证明公钥是谁的** |
| 类比 | 手写签名 | 身份证 |
| 用谁的私钥 | **发送方**的私钥 | **CA** 的私钥 |
